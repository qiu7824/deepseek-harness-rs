# 回复完整性与交付呈现

回复完整性覆盖接收、保存、任务循环和界面呈现。回复结束、工具执行成功与用户目标完成是不同状态，不能互相替代。

## 接收与保存

Responses 事件按照输出项目 ID 和内容块位置合并。终态中省略的项目不会覆盖此前已经收到的完整内容；同一项目的终态内容用于补全该项目。多个消息和多个正文块保留原顺序。

输出上限、未完成状态、拒绝和传输失败分别处理。已接收的安全文字在终态错误后仍保存为会话消息，并标示未完成；未完成的工具调用不执行，也不作为下一次请求中的可重放调用。

SSE 按完整帧处理。同一网络块中先收到有效帧、随后遇到非法编码或错误 JSON 时，先交付有效内容，再报告失败。解析器不会忽略坏数据，也不会把缺少有效终态的连接结束当作成功。

## 有界恢复

| 状态 | 行为 |
| --- | --- |
| 普通非空最终答复 | 正常结束，不增加请求 |
| 明确的 `commentary` 中间更新 | 同一回合继续，连续自动续接最多 3 次 |
| 初始或工具后的空答复、声明工具调用但没有调用内容 | 最多恢复 2 次，仍无有效结果时报告未完成 |
| 有效文字触及输出上限 | 保留各段正文，最多续写 2 次；不提高用户配置的输出预算 |
| 工具参数被截断、只有推理而无可续写正文的上限结束 | 报告未完成，不执行或重放不完整工具 |
| 用户取消或提供方拒绝 | 终止，不进入自动续写 |

续写使用正常的有界上下文，不复制整段历史到提示词。各段正文分别保存，内部恢复提示具有明确来源，不会在界面中冒充用户新发的消息。工具进展不能重新补充整回合的截断续写预算。

网络错误重试继续使用提供方的重试策略。后台任务完成通知与显式目标机制独立工作；这些机制不会因出现一条最终文字就被当作已经完成所有交付验收。

## 界面完整性

- 同一步骤中的不同消息 ID 分别保留；同一消息 ID 的替换以及已声明的重试状态继续使用原有更新语义。
- 通用工具和 `read_image` 的图片通过授权附件接口读取。展开时加载，折叠或分页卸载后释放租约；同一附件的多个消费者共享加载，最后一个消费者离开后释放其对象 URL。
- 一次性子代理正文使用安全 Markdown 呈现。HTTP 链接沿用原有协议限制，本地文件链接通过受控的文件查看通道打开。
- 工具类别、思考标题、已知 Computer Use 动作和轨迹标签从语言资源读取，并随界面语言切换。工具 ID、原始参数和模型正文保留实际内容。
- 通用设置中的回复提示支持“图标显示”和“文字显示”，默认使用文字。选择保存到界面设置并即时生效；图标使用统一的语义图形，悬停提示与读屏名称保留当前语言的含义。

聊天、轨迹和产物页共用可追溯的消息及附件引用。Rust 双向分页、阅读锚点和历史内存预算继续生效，完整呈现不依赖一次加载整段长对话。
