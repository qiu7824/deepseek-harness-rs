# Rust 对话滚动与分页

对话以服务端事件序列为连续记录，浏览器只保留当前阅读位置附近的历史窗口。阅读位置、分页游标和是否跟随新消息分别管理，窗口末尾不等于整条对话的末尾。

## 滚动状态

| 状态 | 行为 |
| --- | --- |
| 阅读历史 | 保持可见消息及其相对视口位置，新消息不改变阅读位置。 |
| 跟随最新 | 仅在窗口包含最新消息且用户选择继续跟随时，随回复增长向下移动。 |
| 定位消息 | 按事件序列加载目标窗口，定位完成后进入阅读状态。 |
| 返回最新 | 作废旧分页结果，装入最新窗口后恢复跟随。 |

一个滚动控制器统一处理滚轮、触摸、键盘、滚动条、消息定位和尺寸变化。用户向上阅读会解除跟随；返回最新入口会明确恢复跟随。内部代码块等可滚动区域优先消费自己的滚动操作。

## 双向加载与锚点

接近已加载窗口边缘时，按视口大小提前请求相邻历史页。内容不足一屏时，仍根据用户的滚动方向请求下一页，不依赖 `scrollTop` 必须发生变化。

锚点由可见消息的稳定标识及其相对视口偏移组成。向前插入、向后追加、裁剪远端页面或展开工具结果时，重新计算该锚点的位置；用户手动改变阅读位置后，以新的位置为准。

单个会话只允许一个历史请求执行。反向操作记录最后的方向，旧请求完成后再执行仍然需要的请求。分页、定位、返回最新和重连使用代次校验，迟到的结果不能写入另一历史窗口或清除其分页状态。

## 内存与更新

历史页面同时受页数和字节预算约束，浏览器不会通过持续翻页累积完整对话。浏览历史期间收到的实时事件也受条数和字节预算限制；超过预算时标记需要恢复最新窗口，不能把不完整缓冲伪装成完整会话。

滚动事件只记录用户意图，布局采样与位置写入由控制器合并处理。等待首个 token、推理和生成回复分别显示对应状态；阶段不变的 token 更新不触发整个对话页面重渲染。

## 回归范围

- 短历史页在滚轮、触摸和键盘操作下继续加载。
- 前插、后追加及窗口裁剪保持当前阅读锚点。
- 连续反向操作保持单请求约束，过期结果不串页。
- 定位历史消息与返回最新不会相互覆盖。
- 流式回复期间可向上阅读，回到最新后恢复跟随。
- 会话切换、页面卸载和连接恢复会清理过期监听与请求状态。
