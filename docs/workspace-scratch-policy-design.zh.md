# 垃圾槽与产物管理

垃圾槽管理任务产生的临时脚本、执行副本、工具输出和构建缓存。正式源码、回归测试、项目配置和交付文件保留在工作区；临时材料按任务登记到应用管理的位置。

## 设置

入口为“设置 → 垃圾槽”，任务内也可从“产物 → 查看产生的垃圾列表”进入。

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| 启用垃圾槽 | 开 | 为新执行分配临时空间和资源记录 |
| 自动清理 | 开 | 后台检查到期资源与可回收缓存 |
| 已结束任务保留 | 7 天 | 到期后进入恢复队列 |
| 失败材料保留 | 14 天 | 为排错保留更长时间 |
| 恢复队列保留 | 3 天 | 期间可恢复；到期后才永久回收 |
| 空间软上限 | 20 GiB | 超限时优先回收没有引用的缓存；不强删固定项或候选产物 |
| 减少过程内容进入上下文 | 开 | 大型纯文本工具结果保存详情并返回有预算的片段 |
| 存储位置 | 系统管理 | 默认在应用数据目录；高级设置可指定新的空目录或已有受管目录 |

位置变更后，新执行使用新位置，活动执行继续使用原位置。位置记录保存所有受管根，内容页可同时列出旧位置的资源。关闭垃圾槽不清空已有材料，上下文保留策略和自动清理开关相互独立。

## 存储边界

每个受管根包含独立的归属标记，并按以下用途存储：

| 目录 | 用途 |
| --- | --- |
| `objects/<id>` | 资源记录、进程引用和写入协调锁 |
| `content/<id>/data` | 运行材料、脚本、执行副本和兼容构建缓存 |
| `vault/<id>/data` | 已保存的完整工具输出及移除文件的恢复副本 |
| `recovery/<id>` | 等待最终回收的材料 |

子进程可写的临时根不包含归属记录、只读输出库和恢复队列。未知目录不会被自动认领。路径检查拒绝符号链接和 Windows reparse point 越界；目录回收只针对已登记对象，不扫描、搬移或删除存储父目录中的其他文件。

Windows AppContainer 会设置自己的临时入口。运行器将该入口连接到本次执行的真实受管目录，退出时先移除入口，再释放容器配置；不会沿入口递归删除真实材料。入口与目标不匹配时保留现场。

## 执行环境

普通 Shell 和原生终端自动获得独立的 `TEMP`、`TMP`、`TMPDIR` 与 `DSH_SCRATCH_DIR`。显式环境参数优先。Cargo 目标缓存按正式项目、平台、架构及工具链环境分组；执行副本通过正式项目身份复用缓存，Cargo 继续负责依赖指纹和并发写入协调。

系统使用现有 Node 安装或配置的运行目录；Windows 也可发现安装器登记的 Node 位置。发现运行时不等于安装依赖。普通对话、插件页面、代码图谱和原生终端不要求 Node；TypeScript 代码执行及项目自身的 Node 构建命令需要兼容运行时。

## 执行副本与交付

`workspace_scratch` 提供以下操作：

| 操作 | 行为 |
| --- | --- |
| `allocate` | 创建脚本、日志或候选材料，返回明确的资源 ID 与路径 |
| `prepare_copy` | Git 根工作区创建 detached worktree，共享对象库，并保全本地修改及未跟踪输入；普通目录创建受限输入副本，也可用 `files` 指定输入 |
| `write` / `read` | 按资源 ID 写入或有界读取；完整工具输出和移除文件的恢复副本保持只读 |
| `inspect` | 读取正式交付目标的当前 SHA-256；不存在时返回 `null` |
| `promote` | 按目标版本交付单个文件；版本冲突时保留候选，不覆盖当前目标 |
| `pin` / `release` | 固定保留或结束候选状态；结束候选状态不会取消已有固定标记 |

普通输入副本默认排除 Git 元数据、依赖目录和常见构建缓存，限制为 20,000 个文件及 2 GiB 输入；更大的任务应显式选择必要输入，原始大文件可保持只读引用。输入复制检测并发变化，不使用可写硬链接把执行副本和正式源码绑定在一起。

运行会原地写入的工具时，将副本路径传给 `pwsh.workdir`。在工作区写入权限模式下，执行副本成为写入边界，正式项目作为只读来源；正式修改仍由文件编辑和交付服务处理。用户明确选择无限制权限时，操作系统写入约束不会替代该选择。

Git 副本进入或离开恢复队列时同步更新自己的 Git 关联。清理会核对创建时登记的管理目录、HEAD 和事务状态；新的提交、分支或未完成 Git 事务会阻止自动回收。不会整树同步执行副本到正式项目。

## 工具结果与上下文

纯文本工具结果超过 12,000 UTF-8 字节时，先保存完整文本，再向模型返回包含头尾诊断和资源引用的有界内容。错误不会因截断而被改写为成功；退出码、异常和必要诊断继续保留。

详情通过 `workspace_scratch read` 的字符偏移与长度读取，单次最多 32,000 字符。详情读取和普通 `read` 不再次外置，避免反复读取循环。图片及其他非纯文本内容沿用各自的内容通道。

临时文件目录不会自动加入后续模型请求。首次生成脚本仍需输出 token；目录外置和界面折叠不能替代实际请求内容控制。磁盘大小不被换算成节省 token 的承诺。

## 回收与恢复

运行中的进程、终端和任务持有引用；进程身份被记录，重启后的仍存活进程继续阻止清理。候选产物、固定材料和待恢复事务受保护。共享缓存还受使用该项目的运行引用保护。

清理先转入恢复队列，在保留窗口内不释放对应磁盘占用。最终回收失败时保留状态和错误，允许重试。归属尚未恢复的运行不会仅凭锁已释放就被判定为无用。

垃圾槽不改写外部 Codex 的会话数据库、JSONL 历史、全局 Temp、用户下载目录或第三方 SDK 缓存。归档任务、删除任务记录和清理临时资源是不同操作。

## 产物页面

“产物”位于“轨迹”右侧，展示任务工具记录及工作区发生的新增、修改和移除。列表支持预览、资源管理器定位、本地工具打开、重命名和移入垃圾槽；文件操作核对当前版本。移除文件保留校验过的恢复副本，恢复不会覆盖已有文件。

工作区扫描跳过依赖与常见构建目录，并有 20,000 项上限；达到上限时明确提示，工具记录的变更继续显示。垃圾槽内容按任务显示保留原因和使用状态，可浏览实际文件及有界文本详情；占用统计在后台进行。

## 验收

- 无目录规则的新任务自动获得独立运行空间，连续构建复用兼容缓存。
- 正式输入不受执行副本写入影响，交付遇到目标变化会拒绝覆盖。
- 模型首次收到的长文本工具输出符合预算，显式详情读取可恢复内容。
- 活动引用、固定项、候选成果和未完成 Git 事务不会被回收。
- 重命名、移除和恢复采用真实文件验证，跨任务访问与路径越界被拒绝。
- 默认插件入口、原生终端、审批、引导输入和手机布局通过同一发布产物验证。
