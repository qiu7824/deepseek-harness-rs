# UU 自连与网页控制探针

网页可以模拟控制面板、截图播放器和输入状态，但不能凭空建立 UU 的设备会话。是否能自连必须同时验证账号身份、设备发布状态、连接回执、连接状态、视频帧和输入回读；单独看到本机设备 ID 或网页按钮都不算成功。

## 探针分层

| 层 | 检查内容 | 成功条件 |
|---|---|---|
| 身份 | `user info` 与 `user_info.ini` 的账号一致 | 账号一致、设备 ID 合法；不输出 token |
| 目录 | `device list` 是否包含本机、是否在线、是否允许控制 | 仅作为“可探测”信号，不直接宣称支持自连 |
| CLI 控制面 | `device connect <本机 ID>` 后轮询 `device status` | 回执包含本机且状态实际出现；空成功回执视为未建立 |
| SDK 控制面 | 使用正常账号和客户端版本请求房间 | 房间协商完成、视频轨道出现；不伪造设备或签名 |
| 视频数据面 | 解码 JPEG/H.264，检查尺寸、时间戳、关键帧恢复 | 帧可解码、时间戳递增、重连后收到关键帧 |
| 输入数据面 | 只对自有验收窗口发送固定文本、按键、滚轮、拖动 | 窗口状态回读与动作逐项匹配；测试默认不发送输入 |
| 清理 | 关闭会话并再次查询状态 | 只释放本探针建立的连接，不触碰已有连接 |

## 当前实测

当前实测 UU 客户端为 4.39.2.1561。本机身份存在，但本机没有出现在可连接设备列表；对本机 ID 执行标准 `device connect` 返回空设备成功回执，状态轮询始终没有本机连接。`uu-desktop` 从已安装客户端读取版本资源及接口布局，4.39.2.1561 的签名数据位置为 `0x3b08118`，旧版 4.38.3.9325 为 `0x3b06e78`；未知版本继续执行布局发现，不按版本字符串拒绝加载。

同一账号的另一台在线设备已通过全部传输层探针：连接、1066×600 截图、1920×1080 H.264 流、60 帧、关键帧恢复、断开、重连和所有者隔离均通过；测试没有发送桌面输入。

2026-09-10 重新验证该在线设备，桌面控制器成功连接并取得真实的 1066×600 Windows 锁屏画面，结束后控制器正常退出。官方 CLI 的 `term --list-sessions` 在环境检查阶段以退出码 5 超时；交互式 `term --new-session` 则明确报告被控端已锁屏，要求系统身份验证。未输入密码或发送终端命令。这证明桌面传输可用，终端命令和桌面应用输入仍需在已登录桌面完成验收。

终端库存查询只是清理基线，失败时不再阻断强制新建连接的真实握手诊断。只有成功握手后才登记终端后台作业；启动失败不会产生“终端已完成”通知。缺失基线或没有远端退出证据时，清理状态保持未确认，不推测远端会话 ID，也不关闭其他连接。

因此当前结论是“本机自连尚未建立”，而不是“网页再加一个判断即可完成”。网页模拟可以用于验证前端布局和本机原生控制，但必须把连接状态、真实帧来源和输入回读显示为独立状态，不能把模拟状态冒充 UU 自连。

## 运行探针

```text
python tools/probe_uu_self_connect.py \
  --cli "D:\\Program Files\\Netease\\GameViewer\\bin\\uuyc-cli.exe" \
  --report D:\\codex操作目录\\uu-self-probe.json \
  --probe-connection
```

探针只使用当前登录账号的本机 ID，连接测试结束会清理本机目标；不会读取或打印令牌，不会发送桌面输入，也不会修改 UU 客户端配置。`webSimulationProvesUUConnection` 永远为 `false`，只有视频和输入回读都通过后，产品层才可显示“可用于 Computer Use”。

如果 UU 客户端以后把本机发布为可控设备，先重新运行此探针；只有 CLI 和 SDK 两层都建立连接后，才继续做自有验收窗口的键鼠闭环。客户端升级时记录版本、文件哈希和实际接口布局；布局能够发现时直接调用，布局数据损坏或无法定位时报告具体加载失败，不能用旧版本偏移盲读新客户端，也不能仅凭未知版本字符串拒绝连接。
