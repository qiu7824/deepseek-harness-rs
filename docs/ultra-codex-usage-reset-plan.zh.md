# Ultra 执行模式与 Codex 账户用量管理

## 执行模式

`executionMode` 保存 `standard` 或 `ultra`，与模型的 `reasoningEffort` 分离。Ultra 在每一步组装请求时，从当前模型支持的能力中解析最高合法档位；Codex 路由不发送原始 `ultra` 推理参数。默认配置、会话选择和冷启动恢复采用同一解析规则，旧会话中的 Ultra 选择仍可读取。

Ultra 的任务提示要求识别可独立执行的工作、使用已有子智能体工具分工，并由主任务检查结果。简单工作可以直接完成；分工是否有益仍由模型判断，调度器不保证每个请求都产生多个子任务。

| 控制项 | 行为 |
|---|---|
| 活动子任务 | 同一根任务最多 3 个；第 4 个请求最多等待 30 秒，并响应取消 |
| 创建和运行次数 | 每个执行阶段最多 12 个不同子任务、36 次子运行；累计准入记录持久化 |
| 深度 | Ultra 子任务不继续创建下一层子任务 |
| 时间 | 默认 30 分钟；`DSH_ULTRA_TIMEOUT_SECONDS` 可配置执行时限 |
| Token | `DSH_ULTRA_TOKEN_BUDGET` 限制已观测的根任务和子任务用量；包含缓存计量，缺失值保持未知 |
| 模型选择 | 同一路由继承当前已解析档位；显式选择其他子模型时使用该路由的选择和能力 |

Token 上限按实际返回的用量检查，无法预知在途请求的最终消耗，不是服务端消费硬上限。发现额度耗尽后停止新准入并取消可控制的子运行；远程执行缺少用量时，不将未知计为零后继续分配。停止与失败沿用子任务运行时的取消和后代清理机制。

## 账户桥接

账户服务通过 Rust 启动官方 Codex App Server 子进程，调用账户协议，不通过创建 Codex 任务查询额度，也不依赖 Node.js。协议依据为 [Codex App Server](https://learn.chatgpt.com/docs/app-server) 及官方 CLI 生成的 JSON Schema；后端是否提供额度、Token 活动或重置卡由当前账户决定。

官方 CLI 是账户桥接的可选依赖。缺失、协议版本不支持或账户身份不可核验时显示具体错误，其他供应商和普通会话继续工作。

每个 `accountScope` 使用独立运行目录，仅为子进程设置 `CODEX_HOME`。账户面板中的“连接用量账号”启动官方设备码登录；需登录与当前模型相同的账户，完成后刷新。服务校验账户读取结果和用量响应中的 `accountId`，不会隐式复用其他客户端的登录状态。账户切换清空旧快照，登出尝试结束桥接登录并关闭进程。

传输采用请求 ID 分发、独立读取循环、有界响应帧和通知队列。请求写入和读取均受超时控制；未知服务端请求返回不支持，不阻塞后续响应。

## 用量与重置卡界面

账户面板显示服务端返回的多个额度桶、窗口时长、已用比例、剩余比例和恢复时间。剩余比例为 `clamp(100 - usedPercent, 0, 100)`；恢复时间按秒时间戳转换到界面时区。缺失值显示“未提供”，不以零代替。

同账户快照缓存 30 秒，手动刷新、账户变化和兑换后重新查询；额度更新通知按桶合并，保留未更新的桶。网络失败可保留同账户最近快照并标记待刷新。账户共享额度、官方 Token 活动统计和 dsh 本地会话用量分别呈现。

| `/provider-auth/` 路由动作 | 用途 |
|---|---|
| `usage-login` | 启动隔离的官方设备码登录 |
| `usage` | 读取额度、重置卡摘要及最近操作 |
| `usage-history` | 读取官方 Token 活动统计 |
| `reset-prepare` | 持久化当前账户的一次兑换操作，不消费卡片 |
| `reset-consume` | 执行指定的已准备操作 |
| `reset-status` | 读取本地操作状态，无需重新兑换 |

这些动作沿用可信来源与账户检查。模型工具 `codex_usage` 只读；不会因为启用 Ultra、达到限额或收到普通“继续”指令而消费重置卡。界面的“使用 1 张重置卡”是明确操作入口，不包括购买或自动补充额度。

## 幂等、断线与恢复

Host 在发送前保存操作 ID、账户 ID、可选卡 ID、幂等键和状态。浏览器只能提交已签发的操作 ID，不能替换账户或幂等键。每个账户目录通过文件锁协调跨进程操作；双击、多标签页、断线重试和进程重启继续使用同一次逻辑操作。

| 返回结果 | 状态处理 |
|---|---|
| `reset` | 记录成功，刷新额度和卡数 |
| `alreadyRedeemed` | 记录此前已完成，不认为又消费一张 |
| `noCredit` | 记录未兑换，不自动创建新尝试 |
| `nothingToReset` | 记录没有可重置窗口 |
| 超时、断线、未知返回值 | 保留结果未确认状态，仅以原账户、原幂等键核对 |
| 兑换成功但刷新失败 | 保留成功结果，用量等待刷新 |

未结算操作不会因为重启、登出或切换账号而被改写为未发生；旧账户操作不能为新账户兑换。

## 维护与验证

前端可维护源文件位于 `web/src/runtime-plugins`，由 `npm run build:runtime-plugins --prefix web` 生成运行模块和 manifest 摘要。Rust 实现分布在模型选择、请求组装、子智能体准入、账户服务和受保护路由中。

回归覆盖合法推理参数、旧选择恢复、子任务准入与累计限制、同账户校验、多额度桶、未知值、兑换的四种结果、重复操作和断线恢复。日常测试使用隔离的模拟服务；不会为发布检查消费真实重置卡。发布包核验前端摘要、核心版本和启动入口的一致性。

升级与回退保留会话数据和兑换日志。旧版本不能识别新的执行策略时，不应删除相关记录来绕过兼容检查。
