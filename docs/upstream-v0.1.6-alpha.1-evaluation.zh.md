# 上游 v0.1.6-alpha.1 评估

## 结论

当前 Rust 版本已覆盖上游与本项目目标直接相关的会话、工具、工作流、附件、桌面控制和浏览器控制基础能力。上游版本中与云端产品、账号计费和托管环境绑定的功能不能直接移植；本项目应通过本地 Host、明确的远程适配器和能力声明保持边界。

## 已对齐能力

| 能力 | Rust 实现 | 验证 |
| --- | --- | --- |
| 子代理与工作流 | `dsh-subagent`、`dsh-workflow-*` | 子代理结果传播、失败分类和生命周期测试 |
| 图片输入 | 附件哈希索引、`read_image`、视觉路由 | 实际 PNG 上传、读取和跨会话隔离 |
| 浏览器控制 | `NativeBrowserAdapter` | Edge 隔离实例真实点击、输入、滚动、标签页和截图 |
| Windows 桌面控制 | 原生控制器与 UI Automation | Win32 控件输入及过期快照拒绝 |
| 搜索与 Shell | 有界进程、取消、超时、权限分类 | 非 Git、沙箱拒绝、COM 拒绝和挂起进程回归 |

## 连接能力边界

Devin CLI 本地版本支持图片输入、子代理和可选 Web Search；Rust 中的 `devin` 模型连接是否支持 OpenAI 原生图像或搜索接口由连接协议决定。连接不支持时必须在调用前返回 `NATIVE_TOOL_UNSUPPORTED`，不得通过重复请求伪造能力。

## 工作目录

本地目录和 Git 克隆工作目录属于当前 Host 的执行范围。cloud 和 SSH 工作目录需要远程执行器、凭据隔离、连接生命周期、取消传播和路径权限协议；在这些组件接通前，界面应明确显示未连接，而不是把远程路径当成本地目录。

## 未完成与验收限制

- cloud、SSH 尚未接入实际远程执行器。
- 没有 macOS/Linux 真机，当前只能做目标平台构建和协议测试。
- GitHub Release 页面发布需要 GitHub 登录凭据；代码推送和发布包可独立验证。
- 上游专有服务、计费、组织策略和托管沙箱不属于可复制的 Rust 本地实现。

## 发布建议

先完成 Git 克隆的本地验收，再接入 SSH 和 cloud 的明确适配器；每个适配器单独声明可用能力、取消语义和凭据范围。发布包必须包含匹配版本的 Web 资源、桌面控制器、Computer Use JS 运行时和许可证文件。
