# DeepSeek Harness Rust：v0.1.7-rc.1 / rc.2 评估

评估日期：2026-09-26。实施基线为 `main` 的 `ad539d20`（开发版本 0.1.3-alpha.35）。上游目标为 [dsh-v0.1.7-rc.1](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.7-rc.1)（2026-09-23）和 [dsh-v0.1.7-rc.2](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.7-rc.2)（2026-09-24）。依据为两份发布说明及 `dsh-v0.1.7-rc.1...dsh-v0.1.7-rc.2` 的 346 个提交（235 个非合并提交）的源码差异。

## 结论

rc.1 的说明汇总了 v0.1.5-rc.3 以来的累计变更，主体已在 [alpha.1/alpha.2 评估](upstream-v0.1.7-alpha.1-alpha.2-evaluation.zh.md) 中逐项处理；本文只把 rc.1 作为对照，不重复计入新开发量。rc.2 的实际增量为 6 项新增、19 项修复、6 项调整和 11 项优化。

本轮按“先修会导致失败或数据问题的缺陷，再补客户端可见差异”的顺序，移植了 6 项上游修复，并在 Rust 端发现并修复了同类的 4 处缺陷（见下表）。剩余项目以 P1/P2 列出，均未计为已完成。所有结论只覆盖列出的测试范围，不代表安装版或其他平台已验收。

## 本轮已实施

| 上游变更 | Rust 实现 | 验证 |
|---|---|---|
| 过长工具输出出现残缺字符并可能导致后续请求失败（`dc07e5a50`） | Rust 字符串不会出现孤立代理项，但存在同类缺陷：子进程输出收集器按字节截取尾部后整体有损解码，截断点落在多字节字符中间时开头出现 `�`；增量读取会把一个字符拆到两次读取。现在跳过被截断的续字节，流未结束时保留不完整的尾字符到下次读取（`crates/subprocess/subprocess-local/src/spawn.rs`） | 新增 3 项单元测试；`dsh-subprocess-local` 全部测试通过 |
| 同上（按字节截断） | Git 差异预览在 2 MiB 处 `String::truncate`，中文等多字节内容会直接 panic；日志导出器按字节切行同样会 panic，且 URL 编码文本中的 `%E5` 等会消耗不存在的参数导致 panic。均改为按字符边界截断，未知格式符保持原文（`web_preview.rs`、`vendor/logger-console`） | 新增 3 项单元测试 |
| 异常退出或安装中断后插件安装、配置保存持续失败（`7e7ba139f`、`910711e6c`） | `with_file_lock` 原先在进程崩溃后永久遗留 `<file>.lock`，此后凭据、Host 设置、项目任务和上传索引的写入都会超时。锁记录改为 PID、主机名和随机值；同一主机上持有者进程已不存在时，经声明文件串行化后接管；兼容旧版纯 PID 记录。另修复一个上游没有的缺口：受保护操作被取消时锁文件不会被删除，现由析构守卫释放（`crates/util/atomic-write`） | 新增 4 项测试：旧/新记录接管、存活或其他主机持有者保持等待、残缺记录不接管、取消后释放 |
| 文件侧栏无法进入目标位于工作区内的 Windows 目录链接（`931505a9c`） | Rust 标准库把 Windows 联接点识别为符号链接，列表原先直接跳过所有链接，联接点目录完全不显示。现在按目标类型列出目标仍在工作区内、且不在受保护目录下的链接；打开时仍由既有的规范化与边界检查约束 | 实际创建联接点的测试：工作区内链接可见，指向工作区外及 `node_modules` 的链接隐藏 |
| 减少浏览器把登录密码填入 API Key 输入框（`4cc76d04e`、`11c051127`） | 模型 API Key 两处、插件与通用设置密文字段两处改为 `autocomplete="new-password"`（Chromium 会忽略密码框上的 `off`） | 相关设置 DOM 回归通过 |
| 折叠的网页抓取卡片可直接点击网址（`61a0ed487`） | `web_fetch` 行的摘要在参数是 http(s) 地址时渲染为新标签页链接，点击和回车不展开卡片；失败行、非 http(s) 协议和未完成的流式参数保持纯文本 | 新增 `tools/tests/web_fetch_link_dom_harness.cjs` 并接入发布流程；相关工具卡片回归通过 |
| 桌面端聊天中的本地 Markdown 图片可预览和放大（`7f0a53dfb`） | Flutter 原先按进程当前目录解析相对路径，Windows 盘符路径、URL 编码及中文文件名无法显示，也不能放大。现在按会话工作区解析相对路径，支持盘符、`file:`、百分号编码路径，点击后可缩放查看 | 路径解析单元测试及点击放大部件测试 |

## 已具备或不适用

| 上游变更 | 判断 |
|---|---|
| 关闭桌面窗口后任务继续运行（`474593468`） | Flutter 客户端以独立进程启动 Host，关闭窗口本身不会结束任务；退出前的任务影响提示尚未实现，列入 P2 |
| 过大的请求扩展字段阻断模型请求（`193f9ce41`） | 上游问题来自 JavaScript 序列化会话日志上传扩展；Rust 适配器没有该扩展机制，不适用 |
| 定时任务与时间上下文默认关闭 | Rust 随附预设未默认启用时间上下文与定时任务，行为一致；启用后的默认刷新间隔（上游 10 分钟）尚未对齐 |
| 新建默认工作区的文件夹名不随界面语言变化（`ff1c7d415`） | Rust 尚无 rc.1 的“首次启动自动创建默认工作区”，工作区由用户选择，暂不适用；实现该功能时须采用与语言无关的目录名 |
| 进行中的对话使用新启用的工具（`bc8c0dbf4` 等） | Agent 循环已按工具基线识别变化（`agent-loop/src/agent.rs`），是否在同一会话内完整生效仍需专项验证 |

- 切换模型时显示等待状态（`c87959bc4`）；不兼容插件提示每次启动只显示一次（`c8b10a16b`）。

## Flutter 客户端补齐（本轮）

与 rc.2 无直接对应，但属于同一批次的客户端完善：

- 剪贴板粘贴：截图等纯图片内容成为 PNG 附件；从资源管理器、访达或文件管理器复制的文件成为附件；表格或文档复制时同时带文字和图片的，按文字粘贴。Windows、macOS、Linux 各自以原生通道 `dsh/clipboard` 读取；缺少该通道的客户端保持普通文字粘贴。右键菜单的“粘贴”走同一逻辑。
- 待发送附件显示图片缩略图，可预览、移除，文件显示名称和大小。
- 附件类型按文件内容识别图片格式，扩展名错误的图片不再被 Host 拒绝；BMP、SVG 等不再被误作图片部件发送。文件夹不能作为附件。

Windows 原生读取已用独立程序在真实剪贴板上验证 24 位自下而上、自上而下、32 位位域、8 位调色板位图、PNG 格式、中文长路径文件列表及损坏数据；macOS 与 Linux 代码尚未在对应平台构建和实测。
