# Rust 垃圾槽简化方案

## 设置

保留“启用垃圾槽、存储位置、自动清理、分类保留时间”四项设置。存储位置由用户选择，留空使用应用管理的位置；各保留时间均可修改。

## 构建复用

同一项目的兼容构建复用受管构建目录，临时 worktree 沿用正式项目身份，不按任务或日期另建整套缓存。独立的一次性测试项目使用自己的临时构建目录。

宿主自动设置执行临时目录和 Cargo 构建输出位置。若所用 Cargo 配置将最终产物目录与中间构建目录分开，两者都要登记。构建目录的位置与分类由执行器处理，无需模型每次申请。Cargo 提供输出位置配置和构建缓存复用能力。[Cargo 构建缓存说明](https://doc.rust-lang.org/cargo/reference/build-cache.html)

## 分类保留

| 材料 | 建议默认规则 |
| --- | --- |
| 一次性测试的构建产物、已结束的临时执行副本 | 释放后保留 24 小时；有效变化须已交付或明确放弃 |
| 正式项目复用的构建缓存 | 连续 7 天未使用后回收；每次实际使用结束后重新计时 |
| 一次性脚本、普通构建和测试日志 | 运行结束后保留 7 天 |
| 必要失败证据 | 保留 14 天；保留错误、重现命令、工具链及必要输入，不因此保留整套构建目录 |
| 用户移除文件的恢复副本 | 保留 3 天恢复窗口，到期后永久删除 |

期限届满且资源已登记、没有进程使用、没有未交付变化或固定标记时，临时材料和可重建缓存直接回收，不再额外等待 3 天。恢复窗口只用于用户移除文件的恢复副本。

共享缓存不能在每次测试结束后清空，否则下次需要重新编译。失败涉及增量缓存、链接产物等构建现场时，固定必要现场后再排错。正在编译、测试或从构建目录运行的程序均阻止相关目录回收。

正式交付物放到指定成果位置。源码、正式测试、配置、锁文件及仍需保留的变化按其项目用途保留；全局 Cargo 下载缓存和 Rust 工具链不套用任务临时目录规则。已有未登记目录不自动清理。

## 后台执行与 token

目录分配、引用登记、计时和到期删除由 Rust 宿主执行，在任务结束、应用启动及定时检查时触发，不向模型发起清理请求，也不把清理明细自动追加进对话。

模型继续使用正常执行工具；只有需要读取诊断详情时才定向读取。新增系统提示、工具定义、模型生成的调用参数及送回模型的结果都会产生相应 token；后台本地文件操作本身不产生模型 token。工具定义计入输入 token，详见 [OpenAI Docs：Function calling](https://developers.openai.com/api/docs/guides/function-calling#token-usage)。

该方案不要求为分配、登记、释放和清理增加逐步模型调用。完整日志存本地，模型默认接收退出状态与必要错误片段；实际净变化应以模型请求的 token 统计核对。
