# 垃圾槽容量与生命周期规则

## 1. 管理目标与边界

垃圾槽应同时管理资源归属、生成预算、复用、保留期限与实际回收，避免临时目录持续增长、重复构建和成果误删。本规范定义容量治理的目标行为与个人预设，作为功能实现与验收依据。

1. 正式源码、回归测试、项目配置、锁文件、可维护工具和正式交付物留在任务目录。一次性脚本、诊断输出、执行副本、测试环境和可再生成的中间文件进入受管区。
2. 文件用途与来源凭据决定分类；名称、扩展名、存放时间、Git 未跟踪状态和所在文件夹不能单独作为删除依据。
3. 活动资源、未交付成果、唯一原件、固定保留项及尚未完成的恢复事务优先受保护。容量不足时限制新增写入，不以超限为由删除受保护内容。
4. 自动回收只适用于已经登记且清理策略明确的资源。既有目录先盘点，再逐项分类；不能把整个旧操作目录直接变成可删除的垃圾槽。
5. 清理效果以目标卷真实可用空间变化为准。移入同盘恢复目录、同盘回收站、改名或标记清理，不计为释放空间。

## 2. 存储与接入

### 2.1 个人路径预设

- 临时操作入口统一为 `D:\codex操作目录`，受管资源位于专用子目录 `D:\codex操作目录\dsh-scratch`。注册记录与资源内容隔离，沿用受管根的归属校验。
- 不再自动创建 `D:\codex操作`、错编码目录或任意新根。路径使用 Unicode 传递，并验证往返读写后仍指向同一目录。
- 正式成果写入任务目录；可重复使用的长期工具归入正式工具项目，不能靠长期固定整个临时目录保存。
- 普通用户添加工作目录时继承全局策略，无需额外选择垃圾槽目录。个人预设采用明确的 D 盘位置；其他电脑使用应用管理的位置。
- 空间不足或受管盘离线时，不静默回退到工作目录、C 盘 Temp 或其他盘。备用存储仅能使用预先配置的受管位置。

### 2.2 管理范围必须可见

受管资源、外部登记资源、未登记历史目录分别显示。外部 Codex、手动终端及其他 Agent 不会因本应用启用垃圾槽而自动受控；它们需要接入统一分配、环境注入和租约接口，才能获得相同的生成预算与回收保障。

外部客户端可以使用受管运行目录并登记用途、来源、进程和结束状态。未接入的目录只显示占用与候选分类，不承诺自动保护在用进程或自动清理。提示词与 `AGENTS.md` 可以指引写入位置，但不能替代宿主或操作系统的写入约束。

显式指定的 `TEMP`、`TMP`、构建输出路径仍应被记录；超出受管范围时标记为外部写入，不能假装已纳入额度。无限制 Shell 能绕过环境变量与受管 API，此模式下必须标明容量治理的覆盖范围。

## 3. 分类保留规则

保留时间从资源被明确释放或最后一次实际使用结束起算，不使用目录创建日期，也不因后台扫描刷新时间。表中自动删除均要求：归属可验证、无活动引用、没有未交付变化、未被固定，且已满足该类恢复与保留条件。

| 类别 | 正常保留规则 | 容量压力下的处理 |
| --- | --- | --- |
| 运行临时文件、下载残片、可重建解压目录 | 对应进程退出并释放引用后保留 24 小时 | 确认为可重建且没有诊断或成果依赖时，可提前永久回收 |
| 一次性脚本与普通诊断日志 | 完成后保留 7 天；完整正文受容量预算限制 | 优先轮转已结束任务的可再生成输出，保留结果摘要、退出码和重现命令 |
| 失败证据 | 最小重现材料与必要日志保留 14 天 | 不因一次失败保留整个构建树；可重建缓存按缓存规则处理，唯一证据继续保护 |
| 文档渲染页、OCR 临时结果、视频代理与试渲染 | 成果及可编辑工程验证完成后保留 48 小时 | 可再生成部分先回收；原始录音录像、照片、设计工程、字体素材及唯一编辑源不适用 |
| Git 执行副本、软件测试副本 | 成果已交付且副本没有独有修改后保留 24 小时 | 无进程占用、无独有提交和数据的副本可优先回收；数据库变化必须先交付或保全 |
| 共享构建缓存、可重装依赖与可再下载包 | 最后使用后保留 7 天，并受共享缓存额度控制 | 按最近使用时间回收无引用的冷缓存，不进入文件恢复队列 |
| 构建验证包、安装包与解压副本 | 发布交付验证完成后保留当前版本及前一成功版本，历史临时包最多保留 7 天 | 回收有正式副本或可验证再下载来源的重复包；发布归档与唯一离线安装包单独保护 |
| 用户移除文件、原件替换前的恢复副本 | 默认提供完整 3 天恢复窗口；可设置更长 | 恢复期限不能因空间压力缩短；不足时限制新增恢复副本并提示处理受保护占用 |
| 候选成果、未提交源码、工程数据库、唯一备份、固定项 | 持续保护；等待明确交付、释放或解除固定 | 计入真实占用，达到额度时限制继续膨胀；不能自动降级成缓存 |

同一目录含有不同类别时应拆分登记；无法拆分或无法证明来源时，整体按较高保护等级处理。文件被模型读取、被恢复事务引用或属于有效重现包时，引用未释放前不能回收。

## 4. 容量阈值与任务准入

### 4.1 个人默认额度

所有容量统一以 GiB、MiB 表示，1 GiB = 2³⁰ 字节。资源大小未知时显示“统计中”，不得当作零占用。

| 项目 | 默认值 | 到达阈值后的动作 |
| --- | --- | --- |
| 所有受管根合计软上限 | 20 GiB | 立即安排冷缓存与到期材料回收 |
| 所有受管根合计准入上限 | 30 GiB | 回收并重新核算；仍超限则暂停新增大资源分配 |
| 单任务普通临时材料 | 2 GiB 初始预算 | 按批申请追加；追加受总额度及卷余量约束 |
| Rust、批量 OCR、视频等重型任务 | 根据历史峰值单独估算；首次按工作量分批 | 预算不足则缩小批量或排队，不通过另建目录规避额度 |
| 共享缓存合计 | 软上限 12 GiB，准入上限 20 GiB | 先回收冷项目；活动项目保持租约保护 |
| 同一项目的重型构建 | 默认 1 个并发 | 兼容构建排队复用；不同平台构建也要独立预留空间 |
| 普通任务日志 | 100 MiB | 分段轮转；保留开头环境摘要、末尾诊断及独立错误摘要 |
| 普通日志全局占用 | 1 GiB | 回收到期日志；必要失败证据单独受保护并计入总额度 |

分类额度是上界，不能相加作为额外可用空间。全局额度覆盖当前位置、旧位置、恢复队列、固定项及外部已登记资源；共享对象只计一次物理占用，不能在每个任务中重复累计。

统计同时区分文件逻辑长度、可获得的实际分配大小与卷真实空闲量。硬链接、压缩文件和稀疏文件不能直接用逻辑长度推算可释放空间；无法取得物理占用时使用带标记的保守估计。清理期间其他程序的写入可能影响卷余量，结果应分别列出删除的资源大小与实际空闲变化。

### 4.2 卷余量阈值

以下阈值按目标卷总容量计算，每次取固定容量与百分比两者中的较大值，并从最严重状态开始判断。

| 状态 | 可用空间 | 行为 |
| --- | --- | --- |
| 预警 | 低于 `max(30 GiB, 卷容量 × 10%)` | 触发一次回收与预算重算，降低大任务并发 |
| 紧张 | 低于 `max(15 GiB, 卷容量 × 5%)` | 暂停新的构建、全量复制、依赖安装和大规模渲染，继续只读分析及受预算约束的小写入 |
| 应急 | 低于 `max(5 GiB, 卷容量 × 2%)` | 阻止非必要新增写入；在安全边界暂停本应用管理的写入任务，保留检查点与最小诊断空间 |
| 恢复 | 达到 `max(40 GiB, 卷容量 × 15%)` | 退出空间压力状态；按任务预算逐个恢复，避免反复启停 |

卷余量规则优先于垃圾槽自身额度。即使垃圾槽未达到 20 GiB，也可能因其他软件占用而暂停新增大任务。磁盘压力不得触发强制结束 WPS、数据库、编辑器或其他外部进程。

### 4.3 分配前必须预留

创建环境、构建、下载、解压、全量复制和渲染前，先申请预留额度，再启动命令。预留须按卷在多个任务及客户端间原子登记，避免多个 Agent 同时使用同一份剩余空间。

任务至少满足：

```text
卷实际空闲 − 其他运行尚未落盘的预留 − 本次预计新增峰值 ≥ 卷安全底线
全局实际占用 + 现有尚未落盘的预留 + 本次预计新增峰值 ≤ 全局准入上限
```

卷安全底线采用“紧张”阈值。预计峰值应包含压缩包与解压结果并存、旧版本与新版本并存、渲染中间帧、校验副本等瞬时占用。已落盘字节从预留中扣除，禁止重复计费。

预算不明时先估算或分批处理；只对已登记的相同项目及工具配置复用历史峰值。执行期间定期补充计量，发现增长超出预算时停止开启下一批写入，并在可安全停止的位置处理当前任务。

准入上限是调度规则，不等于文件系统字节级硬配额。对于无法拦截的任意原生进程，仅有轮询不能保证不超写；需要进程写入限制或文件系统配额才能提供强保证，界面必须如实区分。

## 5. 减少重复生成

### 5.1 Rust 与源码副本

- 同一正式项目的执行副本使用同一项目身份，兼容的工具链、目标平台与构建参数复用构建缓存；会话 ID、日期和 Agent ID 不进入共享缓存身份。
- 缓存身份记录实际使用的编译器版本、目标三元组及影响产物的构建参数，避免仅凭空环境变量认定兼容。具体依赖指纹和并发写入仍由构建工具负责。
- 一次性测试项目可以拥有独立缓存，但必须登记预算与期限；不能通过 `target-日期`、自定义输出目录等方式逃逸计量。
- 临时 Git 工作副本优先采用共享对象库的 worktree。普通目录只复制必需输入，默认排除已有构建树和依赖目录，源文件不可通过可写硬链接绑定到执行副本。
- 依赖库、工具链和长期 SDK 应复用正式安装，不为每次任务重复复制完整运行时。全局安装与缓存不能直接按临时项目缓存清理。
- 不在每次构建前清空缓存。优先维护少量活跃缓存，整体回收冷缓存单元，避免直接逐扩展名删除内部文件破坏状态。

### 5.2 软件、工程资料与媒体

- 筑业、WPS 等工具优先使用既有安装。确需隔离运行时，登记独立的软件副本及数据库差异，默认每个任务只创建实际需要的实例数量。
- 大型规范 PDF、图纸、照片及录音录像优先只读引用。修改型处理仅复制目标文件，批量渲染、OCR、转码按页或片段处理，避免完整源库的多份副本。
- Office 处理统一使用 WPS Office。临时 PDF、页图及校验图可以自动回收，正式 Word、Excel、PDF 和其必要编辑源必须通过交付验证后才能释放关联临时材料。
- 复制成功或视频能够播放不等于交付完成；还应确认完整性、可编辑工程、外部素材引用和正式目标可用。仅存在于临时目录中的有效修改或素材继续保护。
- 相同下载对象以来源身份和内容校验复用；压缩包、展开目录、验证副本与发布副本之间登记关系，避免把每一步都永久保存。

## 6. 清理事务与真实空间回收

### 6.1 清理顺序

1. 在注册锁与资源租约下，处理已经到期的恢复队列，复核恢复窗口及文件归属。
2. 永久回收可再生成、无引用的临时文件、下载残片和冷缓存。
3. 回收已完成交付、没有独有变化的执行副本与可再生成渲染材料。
4. 轮转到期的普通日志与重复验证包；保留受保护证据及发布归档。
5. 重新读取目标卷空闲空间与受管占用。未达到预算要求时，返回阻塞原因与受保护占用，不扩大到任意用户目录。

可再生成缓存默认永久回收，不经过 3 天恢复队列；此行为必须在设置中明确展示。用户移除文件及替换前原件使用独立恢复策略，不能沿用缓存快速回收规则。

移动到恢复队列不会从占用总量扣减。只有最终删除成功后才减少估计占用，随后用卷空闲量核对实际效果。跨盘迁移必须分别报告源卷与目标卷变化，不能将迁移算作整机垃圾减少。

### 6.2 安全与失败处理

- 回收前重新验证规范化绝对路径、所属卷、受管根身份、资源标识与对象类型；拒绝路径越界和符号链接、junction、reparse point 穿透，绝不递归处理受管根的父目录。
- 核验租约、进程启动身份及子进程引用；不能仅按 PID、锁文件年龄或界面“任务完成”判断进程结束。
- Git 副本检查独有提交、未提交差异、未跟踪输入和未完成事务；数据库、Office 与媒体编辑工程检查未交付变化。状态不确定时保留。
- 活动引用检查与回收操作采用一致的锁协议，避免检查后资源重新被使用。崩溃后先恢复事务和进程归属，再允许清理。
- 删除失败记录部分完成状态与实际剩余，后续幂等重试。不能把“已加入清理队列”显示为“清理成功”。
- 恢复队列满时不提前销毁仍在窗口内的用户文件；先阻止需要新增恢复副本的操作，提供明确的空间处理入口。

### 6.3 触发与通知

任务结束、主程序启动后恢复完成、达到额度、跨越磁盘阈值及分配大资源前触发检查；常规后台检查每 15 分钟一次。重复触发合并，压力状态下提高余量检查频率，目录体积使用增量计量与周期校准，避免频繁全盘扫描。

仅在进入新的压力状态、任务被阻塞、清理失败或需要处理受保护材料时通知。状态未变或后台回收正常完成时保持安静。主程序未运行时不能声称后台规则仍在执行；独立后台服务须有清晰的启用状态。

## 7. 历史目录纳管

历史操作目录采用独立台账，至少记录路径、大小、可能用途、归属证据、是否唯一副本、活动性、建议动作和可信度。扫描只读取必要元数据，未知项进入待分类列表。

- 编译树：结合项目、构建标记和产物位置确认；仅凭文件夹叫 `target` 不能整目录自动删除。
- 整理移出的文件：检查原位置、内容和正式归档；移出的源码、工程、媒体和唯一历史版本默认保护。
- “待删除”“缓存隔离”“backup”等目录名不构成删除授权；必须有明确的分类记录与有效保留期限。
- 构建缓存、依赖副本与可重建临时包可以逐项登记后交由策略管理；首次登记不得暗中缩短原有恢复窗口。
- 历史冷数据可在已配置的其他位置归档，但迁移仍消耗目标空间；复制核验、引用更新和源删除须形成完整事务。
- 规范库、工资表、工程资料、筑业数据库、Live2D/PSD 工程、原始录音录像、模型权重与唯一离线包不属于默认自动清理范围。
- 系统分页文件、应用安装目录、全局 SDK、浏览器登录数据以及外部客户端的会话历史不由垃圾槽回收。

## 8. 工具输出与上下文

垃圾槽内容不自动进入文件搜索、代码图谱、工作区摘要和后续模型请求。普通工具结果返回执行状态、必要诊断、变化摘要与资源 ID，大段正文按预算外置；详情可按需有界读取。

默认普通文本工具结果保留 12,000 UTF-8 字节以内的必要内容，单次详情读取最多 32,000 字符。退出码、失败原因和截断标记必须保留；正文过期后明确显示“详情已回收”，不能返回伪造结果。

正文因日志额度被轮转或截断时，元数据必须记录保留范围、缺失范围及原因，不能再标记为完整日志。必要失败证据、成果及可复现输入不通过普通日志轮转释放。

避免默认递归打印完整文件树、打包清单和大型 JSON。复用已经登记的脚本及结果版本，后台计量只返回汇总。界面折叠、文件搬家和磁盘删除不会自动减少已发送的上下文，历史压缩应由请求组装策略单独管理。

## 9. 设置与实现顺序

设置页保留“启用垃圾槽、自动清理、资源保留、容量与磁盘余量、减少过程内容进入上下文、存储位置”六组内容。高级设置提供分类覆盖、任务预算、缓存预算、已登记位置和外部客户端接入状态。

关闭自动清理仅停止回收，保留容量计量与空间告警；是否继续进行写入准入由独立开关控制。关闭垃圾槽不删除已有资源，不抹除恢复记录，也不自动修改外部程序的环境。

实现按依赖关系推进：

1. **容量基础**：跨受管根总计量、按卷余量、明确的实际释放统计、资源类别及保留原因。
2. **分级回收**：可重建缓存直接回收、用户文件恢复窗口、失败证据拆分、可重试事务。
3. **预算调度**：大操作预检、跨任务原子预留、超限排队、活动写入增长监测和状态通知。
4. **生成约束**：项目身份稳定的缓存复用、执行副本限制、批量处理、显式路径与外部客户端登记。
5. **历史治理**：旧目录盘点、保护原件、逐项纳管及归档，提供可审核的动作清单。

## 10. 验收条件

- 多个任务同时申请空间时只能消费已分配预算，不能重复预留同一份卷空闲量。
- 两个受管位置各占 15 GiB 时，全局统计必须为 30 GiB，而不是分别显示未超限。
- 受管区很小但 D 盘可用空间不足时，大型构建仍被正确限制；普通读取可以继续。
- 冷构建缓存回收后真实空间增加；移入同盘恢复队列时释放量显示为零。
- 超限时存在活动编译、候选成果或尚在恢复窗口内的原件，系统保留它们并说明阻塞原因。
- 同一项目连续创建多次任务不会复制多份兼容构建缓存或完整 Git 对象库。
- 失败构建保留足够重现证据，同时允许释放没有诊断价值的可重建大文件。
- 日志和统计文件持续产生时受自身额度控制，不因盘点制造新的无界占用。
- 原始图纸、工资表、工程数据库、PSD/Live2D 工程及录像即使位于旧操作目录，也不会因后缀或目录名被自动删除。
- 主程序崩溃、进程仍在运行、磁盘离线、路径被替换及文件被占用时，不发生越界删除或误报释放。
- 未接入的外部客户端显示为未受管，不把提示词约定展示为已强制生效的容量限制。
- 用户恢复文件时遇到同名正式文件不得覆盖；回收后工具日志引用保持可解释的状态。
