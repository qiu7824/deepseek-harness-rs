## 仍在发生的缺陷与处理

### P1：环境检查本身阻断执行

`execution_profiles.rs:802` 对沙箱包装后的进程整体执行施加五秒预算，没有先区分沙箱 ready 与被测程序执行阶段；超时结果又成为正常命令的硬前置失败。真实对话中同一问题跨 Shell、Python、多个任务反复出现。

Node 样本已证明程序在宿主存在且能运行，但不能据此认定沙箱内可运行；同样不能把沙箱初始化超时解释为 Node 未安装。120 秒启动超时的底层原因仍须读取可信运行器阶段证据，不能只把五秒上限调大后宣布修复。

处理：分离初始化、ready 握手、程序探测和输出回收；校验真实可执行路径；失败结果携带阶段与可恢复动作；在同一权限和运行时身份下完成探测及实际任务验收。

### P1：环境变化后恢复流程自我阻断

UI 会话 seq 37438—40944 共 7 次因环境指纹变化被拦，其中包括 grep 和 read。`task_execution.rs:115` 的环境守卫不豁免只读检查工具，虽然同文件已经将其分类为 ReadOnly。

守卫要求检查旧效果，却又阻止读取效果证据。与此同时，`store.rs:350` 将所有非只读失败归为 Unknown，未区分“审批拒绝、命令未启动”与“可能产生部分写入”。会话最终累积 10 个 Unknown 步骤。

工具的 recover 只返回状态，不执行环境迁移。人工入口提供 confirm/resume/reconcile，但未发现用于更新契约环境指纹的动作；安装页面启动清单也未加载 `ui-task-execution` 插件。仅要求用户“手工清理或新开会话”不是完整恢复方案。改变权限模式是故障触发条件，恢复设计缺陷不应归责于用户。

处理：在现行权限下允许只读取证；依据可信调度记录区分未派发、确定失败、未知效果；提供环境迁移与相关证据失效/重验流程；将恢复 UI 接入正式发布。不能直接批量清除 Unknown 或接受模型口头保证。

### P2：工具使用与错误恢复能力不足

主 UI 样本的 4 次 `arguments must be an object`，实际原始参数分别包含非法 JSON 转义、缺失分隔符、未转义控制字符，并非单纯选错字段。Python 原始字符串以反斜杠结尾、PowerShell 引号错误、JS 少闭合括号也有明确记录。代码语法问题属于本次模型输出质量问题；模糊报错和过长的嵌套脚本调用放大了恢复成本。

处理：保留 JSON 解析的准确位置和原因；复杂逻辑使用受管理脚本文件与语法检查；短结构化 argv 调用；相同错误无新证据时停止原样重试。

PDF 交给文本 read、PDF 交给 read_image、GBK 日志交给 UTF-8 read、尚未生成就反复读取结果文件，体现文件类型路由、编码识别、任务完成判定不足。处理：文件类型与渲染能力发现、显式编码、可追踪执行结果，以及已验证的 WPS/PDF 作业流程。

### P2：自动诊断尚未转化成可复用经验

处理：先补稳定错误码分类和会话证据跳转；将“观察到错误”“有修复候选”“同场景回归通过”“实际复用成功”“再次复发”分别记录。恢复关联采用执行身份、资源身份和明确的修正关系，不把任意后续成功当作故障已恢复。经验应绑定版本、工具定义和运行环境，不批量将历史 pending 改为 verified。

## 能力限制与外部状态

- `NATIVE_TOOL_UNSUPPORTED`：相应连接不具备原生搜索接口，属于模型连接/工具路由能力边界；换同样参数重试没有作用，应路由到可用搜索服务。
- `The provider did not execute native web search`：不能直接推断所有搜索实现均缺失，需要检查实际选中连接与请求适配。
- AUTH、RATE_LIMIT、TRANSPORT：账号、配额、网络或适配层问题，不能归为通用推理能力不足；需分别核对原始请求状态。
- 设备未连接、文件占用、权限拒绝：可能是正常环境状态。应保留可验证的对象、操作、阶段和错误码；仅凭“拒绝访问”不能断言 WPS 独占文件或要求扩大权限。
