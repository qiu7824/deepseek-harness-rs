# Agent 能力缺口与优先级

核对日期：2026-09-16。依据当前工作树、既有实现文档与执行回归；源码存在不等于当前安装版已完成验收。本清单不表示参考项目均完整具备每一项能力。

## 已有能力基础

已有工具和 MCP、技能动态加载、持久会话与上下文压缩、记忆和验证经验、目标与定时机制、后台作业、子 Agent/团队协作、代码图谱、文件产物管理、浏览器/Windows 桌面和 UU 通道。工具发现与宿主 environment_probe 已有实现及 Host 接线，不能再列为从零缺失。

这些功能的存在不能替代具体后端、真实账户、平台和业务场景的验收。

## 关键区别

### 任务级断点不等于日志耐久检查点

`session-checkpoint-policy` 保护模型请求、工具分派与步骤记录的持久性。它不意味着进程可从任意指令恢复，也不意味着外部系统会回滚。恢复控制面应基于步骤 ID、执行身份、已知副作用和验证证据决定继续、重建或停止。

### 产物交付不等于自动内容验收

`workspace_scratch` 已支持 prepare_copy、inspect、promote 和 expectedSha256；这是重要基础。仍需任务类型对应的检查器：代码编译/测试、文档页数与布局、图片解码与尺寸、表格公式/数据约束。检查器只证明其覆盖范围，无法验证的部分必须明确标注。

### 本地能力缓存不等于多环境运行时

environment_probe 固定目录当前包含 Python、Node、Git、rg、pwsh、FFmpeg、WPS。Python 模块定位不证明原生依赖可以导入；宿主成功不证明沙箱或远端成功。执行环境身份和检查级别必须加入能力结果及缓存键。

### 应用控制工具不等于完整桌面产品能力

现有浏览器标签页、上传、截图、视频采样与 Windows UIA 是可用基础。长期应用授权、细分剪贴板授权、模型原生协议适配与 Unix 桌面实机兼容是独立能力，不能通过同名工具或一次截图成功推断。

## 推进范围

G01—G08 的完整设计已集中在 [统一执行修复方案](unified-environment-execution-repair.zh.md)：执行与环境能力见第 2—11 节，任务验收、断点恢复、远端执行、应用权限、评测和技能改进见第 15—20 节，覆盖关系见第 21 节，集中验证、修复及提交推送约定见第 22 节。本文保留为缺口与证据索引。

远端执行、应用授权和持续技能改进应独立设计，不全部塞入 Shell 兼容补丁。消息渠道数量、主题和面板布局可以按产品需求扩展，但不能替代执行与交付正确性。
