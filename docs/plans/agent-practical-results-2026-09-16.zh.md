## 缺陷与处理

| 问题 | 证据 | 处理与复验 |
| --- | --- | --- |
| 输入提示改变布局 | 输入框获得、失去焦点时，发送按钮顶部坐标从 621 变成 645，移动 24 像素 | 提示区域保持固定高度，文字只在输入获得焦点时可见；修复后两种状态均为 621 |
| 接收确认不够严格 | 前端原来只判断 RPC 成功，没有检查 `accepted` | 只有明确接收才清理草稿和释放附件；拒绝、传输失败的回归检查保留输入所有权 |
| 外部执行目录缺少自动审批 | 工作区外路径在沙箱子进程中可能表现为不存在，容易被误判成编码或文件缺失 | 对显式外部 `workdir` 在进程启动前申请单次目录权限；批准只改变本次执行的目录范围，源项目只读，会话工作区不变 |
| 审批很快消失 | 真实历史记录显示请求在 30 秒后 `timed-out` | 默认等待改为 300 秒；保留明确设置的超时时间和无人确认策略；实测超过 30 秒仍可拒绝 |
| Python 中文输出乱码 | 文件内容正确，重定向 stdout/stderr 出现乱码 | 命令子进程采用 UTF-8 Python 输出；真实模型调用正确返回中文和 ✅，stdout/stderr 均完整 |
| 原生 stderr 被误当成 PowerShell 失败 | `unittest ... 2>&1` 在 Windows PowerShell 中触发 `NativeCommandError` | 错误提示明确区分 stderr 和退出码，给出已有原生探测函数的恢复方式；没有放宽命令失败策略 |

外部 `workdir` 审批属于命令执行权限，不涉及切换用户的会话工作区。批准前目标文件不存在；批准后生成预期内容。后续命令重新请求审批；拒绝后目标文件仍不存在，没有执行重试。原会话工作目录持续为 `agent-baseline-a`。

## 输入与恢复

- 真实按钮发送、Enter 发送、中文多行和编号内容均经过检查。
- 60 秒命令运行时输入后续草稿，点击停止后命令终止，草稿完整保留。
- 更新运行程序后，保留的草稿仍可发送，并得到 `CANCEL-RECOVERY-OK`。
- 拒绝跨目录执行后可以继续普通对话及中文命令。
- 快速切回会话后，三次带事件跟踪的发送均接收并回复，输入长度和发送时长度一致。
- 自动化快速连续操作中曾出现首击未进入接收链路、再次点击成功的情况；三次跟踪未再次复现该状态。尚不能将所有偶发发送问题归因于提示布局，也没有观察到这几次操作丢失已持久化消息。
