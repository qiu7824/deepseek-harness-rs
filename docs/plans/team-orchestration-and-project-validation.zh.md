# 自动团队协作与项目实战验收

## 交付目标

用户在模型选择左侧开启团队模式并提交一次任务，系统依据已保存的团队方案完成规划、分工、执行、验收、有限返工与必要升级。角色、模型、权限与上下文策略均可配置；每个参与者拥有独立会话和可查看的执行记录。

团队模式必须具备可直接操作的设置、控制和状态界面。只有开关、只读面板或提示词草稿不构成完成。

## 当前基线与缺口

| 范围 | 当前能力 | 必须补齐 |
| --- | --- | --- |
| 界面入口 | 会话标题栏的团队面板 | 模型选择左侧的会话级团队开关、状态、暂停／继续／停止 |
| 配置 | 全局 enabled 与 maxMembers | 多方案编辑器、自定义角色、完整模型路由、流程与预算设置 |
| 成员 | 独立子会话、成员通信、共享任务 | 按角色选择模型与执行权限、明确的成员对话入口 |
| 运行方式 | 模型主动调用 agent_team | 用户一次下达任务后的事件驱动调度与验收闭环 |
| 上下文 | fresh／fork | 结构化简报、按需文件摘要、失败日志与有界结果交接 |
| 观测 | 成员和任务状态 | 任务树、失败原因、每角色 token、重试、升级和人工介入次数 |
| 证据 | 单元、组件和模拟模型端到端测试 | 使用真实模型完成项目产物并进行独立验收 |

## 产品契约

### 团队按钮与会话

- 在模型选择左侧提供团队按钮，复用已有按钮高度、圆角、线性图标、主题颜色、提示和键盘焦点样式。
- 区分功能总开关、新会话默认开关、当前会话开关和按钮显示设置。
- 会话开关即时保存，无须重启。运行中的任务使用启动时的配置快照；配置变更作用于下一项任务。
- 明确显示关闭、待命、规划、执行、验收、等待审批、受阻、已停止和完成状态。
- 主对话负责目标与最终交付；规划、调度、执行等成员各有独立上下文与对话。可以从团队面板打开成员记录，并明确消息接收者、发送来源及运行状态。
- 停止主任务会递归停止团队成员；继续操作不得重复已完成的工作。关闭模式不得留下无归属的后台成员。

### 团队方案和角色

- 支持方案的新建、复制、重命名、删除、默认选择、导入和导出。
- 角色可新增、修改和删除，不固定为三个角色，也不硬编码具体模型组合。
- 每个角色保存名称、职责、provider、model、reasoning effort、最大输出、执行轮数、并发和超时。
- 模型从现有目录选择；验证实际路由、能力、推理等级及输出上限。不可用时显示具体问题，不静默替换模型。
- 配置工具白名单、文件读写范围、成员通信、创建下级和升级权限；限制必须在执行层生效。
- 检查委派与升级关系的循环、无效角色引用、并发写入冲突和任务依赖循环。

### 自动调度与上下文

- 复用 agent-team 的持久任务板与消息队列，增加独立的运行控制服务。
- 按方案调用规划角色，生成目标、约束、任务依赖和验收条件；调度角色派工并验收执行结果。
- 成员完成、失败、超时和审批事件触发下一步，不以模型反复询问状态维持流程。
- 默认交接简报与相关文件摘要；失败时附带必要错误。完整历史传递为显式选项，默认不复制其他成员的推理和完整工具输出。
- 返工次数、升级条件和升级对象均可配置。达到上限后进入明确的受阻状态，不无限重试。
- 任务包含优先级、角色、前置依赖、写入范围、验收标准和最大尝试次数。
- 并行写入通过实际范围约束、排队或隔离工作树处理；任务板中的文字说明不能代替权限控制。

### 预算、停止与恢复

- 汇总所有角色的输入、输出、缓存 token、执行时间和重试用量。
- 费用只依据已知价格计算；未知价格显示未知，不以零费用代替。未经配置的自动换模不可作为预算耗尽后的默认行为。
- token、时间、轮数、并发和返工上限均须实际限制执行；触限结果可以是停止或请求用户决策。
- 配置版本化并兼容旧 enabled/maxMembers 设置；历史会话保留运行时配置快照。
- 重启后恢复成员、消息和任务的归属；重复请求使用幂等标识，不能重复派工、投递或覆盖新文件。

## 实战测试方案

### 测试环境与记录

实战使用独立项目和测试会话。模型从当前已配置且可用的目录中选择；角色组合是测试参数。真实模型实战与模拟故障测试分别记录，模拟结果不能代替真实任务完成。

每个案例保存会话／成员／任务／工具调用／审批标识、配置快照、模型路由、开始和结束时间、产物、测试输出、错误码及恢复结果。操作脚本、运行日志和中间证据位于独立操作目录；正式方案、报告和交付产物位于项目任务目录。

### 案例矩阵

| 编号 | 项目和轮次 | 主要验收 |
| --- | --- | --- |
| P01 | 小型 Web 应用：需求→实现→需求变更→修错→交付，至少 5 轮 | 页面可用、输入和续聊可用、刷新与会话切换不丢草稿、产物可打开 |
| P02 | 小型 Rust 工具：接口→实现→测试→边界缺陷→修复→复验，至少 6 轮 | 编译和独立测试通过，失败不被报告为成功，错误修复可复现 |
| P03 | 两个工作区交替操作，至少 4 轮 | 输入、工具目标和审批归属正确；未批准前不能写入另一工作区 |
| P04 | 同一任务以单模型、两层和三层团队分别执行 | 真实完成率、全团队 token、费用可知性、时间、返工及人工介入次数可比较 |
| P05 | 团队并行修改、依赖任务和冲突任务 | 角色路由正确，写入冲突受控，任务不能绕过前置依赖或角色权限 |
| P06 | 运行中暂停、停止、成员失败、断线和应用重启 | 无残留运行、错误可定位、能够继续或明确说明阻塞，已完成产物不重复覆盖 |

### 输入与交互检查

- 新建空白会话、已有会话、成员对话以及不同工作区之间切换后，都能点击、输入、选择文字和发送。
- 覆盖中文输入法组合、粘贴、多行、Ctrl+Enter、附件单独发送、排队与插话。
- 覆盖模型弹层、设置弹窗、团队面板、审批卡片打开和关闭后的焦点与遮挡。
- 覆盖发送失败、取消、重连、隐藏／显示页面、刷新和重启后的输入状态与草稿恢复。
- 每次出现不能输入或不能发送，记录实际 disabled/readOnly、遮罩、焦点、会话阶段和请求状态；区分框架故障与明确的运行限制。

### 跨工作区审批检查

- 审批应说明发起会话、工作区、工具、目标路径、理由和授权范围。
- 分别实测批准一次、拒绝、取消、超时、切换工作区后处理、父子成员请求和重复响应。
- 批准仅作用于对应调用；拒绝、取消或超时后不能继续执行或自动扩大权限。
- 返回原会话后能继续输入；处理一条审批不能解除另一会话或另一工作区的限制。
- 对所有越界写入使用测试文件与前后哈希证明，不使用用户真实文件作为破坏性测试对象。

### 缺陷闭环

每项缺陷需包含最小复现、期望／实际结果、严重度、根因、修复提交和复验记录。固定场景至少连续通过三轮；随后回到真实项目流程验证任务最终完成。UI 可点击、HTTP 成功、模型声称完成或编译通过，均不能单独作为项目成功证据。

## 实施顺序和退出标准

当前执行优先级为[现有单 Agent 多轮实战验收](current-agent-practical-validation.zh.md)。团队实现与团队实战在基础交互问题处理后推进。

1. 固化角色／方案／会话／运行状态的数据契约、迁移与安全边界。
2. 完成原版风格的按钮、设置编辑器、成员对话和直接控制操作。
3. 接入角色路由、事件驱动调度、上下文交接、实际权限与预算限制。
4. 执行案例矩阵，逐项修复输入、审批、无法完成任务和恢复问题。
5. 在同一提交上完成回归、正式包实测、数据保全校验和完整发布。

可操作的团队界面、自动执行闭环、实战产物、独立验收结果和可复核的缺陷记录缺一不可；有未验证项时必须明确保留状态，不能计为完成。

## 版本与发布规范

- 目标发布线为 **0.2.0-beta.1：自动团队协作预览**；稳定性结论由实战验收决定。
- 候选构建通过 workflow_dispatch 触发，在完整验收前不创建新的公开版本标签。
- 同一版本的失败候选以 Actions 运行记录区分，不使用连续 r1/r2/r3 标签代替正式版本规划。
- 全部目标平台验证通过后，给对应提交创建一次正式标签，并提升该次已验证的完整产物。
- 发布说明中文在前、英文在后，列明功能、修复、实际限制、升级方式、包类型和校验和。
- README 的下载入口指向已验证发布页；提交页、标签页和 Release 页各自职责明确，未发布提交不充当下载页。
- 保留已发布版本及其标签。未发布失败标签先盘点引用和恢复信息，再清理明确无发布依赖的临时标签。
- Core、Skin、Free 共用同一应用实现；Free 仅收录对应二进制实际验证通过的模型。各平台安装包、便携包与校验和必须完整关联正式 Release。
