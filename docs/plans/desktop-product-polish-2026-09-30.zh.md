# 桌面产品体验收敛方案

## 产品边界

官方桌面客户端的安装版本为 `0.2.0-rc.2`，使用独立的 Electron 发行与更新源；Flutter 客户端为 `0.1.3-alpha.38+38`，本地构建标识为 `20260930-settings-fix`。两者的产品身份、用户配置、登录能力和更新渠道分别管理。

## 主界面

| 区域 | 官方界面的可见行为 | Flutter 当前状态 | 调整目标 |
| --- | --- | --- | --- |
| 会话主导航 | 对话、轨迹两项常驻 | 会话、轨迹、产物、项目任务、代码图谱、上下文六项并列 | 删除项目任务；保留会话、轨迹、产物、代码图谱、上下文五项原有位置与行为 |
| 工具工作台 | 右侧独立区域，入口突出工作区文件、终端、浏览器 | 多工具标签已有实现 | 删除项目任务入口，其他工具标签与主会话入口保持原有关系 |
| 输入区 | 附件、访问模式、模型及思考强度组成紧凑操作行 | 附件、权限、计划和模型功能已有，常驻入口较多 | 主操作保持稳定；低频命令进入加号菜单；访问模式与模型来源明确 |
| 回合信息 | 完成状态、用量、时间以轻量控件展示 | 本轮用量与耗时弹层已有实现 | 复用现有数据和弹层，统一排版、触发方式、行高及数值对齐 |
| 会话统计 | 轮次/速度、token/缓存、上下文三个独立入口 | 底部主要统计仍是一长行文字和 Tooltip | 三个紧凑入口，分别展开会话耗时、用量和上下文详情 |
| 侧栏底部 | 单一头像/账号菜单；菜单内含设置、反馈和退出 | 多个订阅提供商按钮重复进入同一账号页面，另有设置入口 | 保留直接打开的「设置」按钮；已登录账号以紧凑汇总显示在设置上方 |
| 应用菜单 | 关于、检查更新、管理命令、退出 | Flutter 缺少直接的软件更新入口 | 设置中提供「关于与更新」，菜单提供检查更新快捷入口 |

会话统计沿用真实字段：模型耗时、首 token 延迟、输出速率、输入与输出 token、缓存读写、上下文占比。回合用量、会话累计量与账号额度分别展示；缺失指标显示暂不可用，不以 0 替代。不同模型、请求和缓存条件下的速度数值不用于直接比较客户端性能。

正文默认阅读宽度、用户消息与助手消息的位置、完成状态分隔线、操作栏密度和浮层边缘继续采用同一设计系统。顶部五项主功能保持常驻；定时任务保留可见直达入口，知识库收进工具菜单。定时规则、内容和运行记录保留。

## 项目任务退役范围

`0.1.3-alpha.38` 已退役任务契约、强制验收、完成门禁和自动验收续接。独立的工作区级项目清单另行完整退役，移除以下路径：

- 会话「项目任务」页签。
- 工作台 `project-tasks` 页签与加号菜单。
- 小菜单 `tasks` 开关。
- Host 的 `project_tasks` 工具与 `project:tasks` 自动上下文。

整套退役独立项目清单：同时移除 Flutter/Web 入口、默认模型工具注册和自动上下文注入；旧入口调用返回明确的退役结果。既有文件与历史事件保留，停止新的写入。普通会话待办、计划模式、团队任务、后台执行与定时任务保持各自职责。

验收覆盖「主界面、工作台菜单、设置、模型工具目录及自动上下文均不再出现」，而不只验证页签隐藏。

## 账号与连接

侧栏底部固定保留「设置」按钮，点击直接打开设置。登录后在其上方显示账号摘要：单个服务显示提供商与掩码账号，多项服务使用一行汇总；未授权时不增加额外账号行，账号配置仍可从设置进入。需要重新授权时使用汇总提示，不将授权存在误标成服务健康。

点击后弹出轻量菜单：

| 分组 | 展示内容 | 主要动作 |
| --- | --- | --- |
| 订阅账号 | 提供商、账号别名或掩码邮箱、当前账号、已授权/需重新登录 | 切换账号、查看详情、重新登录 |
| API 连接 | DeepSeek 等连接名称、已配置/缺少密钥 | 管理连接 |
| 外部工具 | Claude Code 等工具名称及登录状态，标明用途 | 打开对应管理页 |
| 通用操作 | 管理订阅账号、API 连接与模型 | 进入对应设置详情 |

账号退出、凭据移除等操作保留影响核查，放在详情页。输入框右下只负责当前会话的模型和思考强度，并显示该模型使用的连接；切换模型不隐式注销其他账号。

现有 Host 可提供账号标签、有效账号范围、是否当前账号、重新登录标记及到期信息；`signedIn` 不代表模型请求已通过联网校验。Codex 用量接口可接入，按实际返回的额度窗口、重置时间和更新时间展示，历史快照需标明；账号/Host 切换后清除旧快照。

当前仓库的 DeepSeek 连接基于 API key，不具备官方客户端的 DeepSeek 网站账号登录。统一入口不能冒充官方用户身份，也不生成缺失的头像、套餐或额度信息。

## 软件更新后续专项

用户流程采用：自动检查 → 下载准备 → 有任务时延后 → 重启更新 → 恢复会话位置。下载进度、失败重试和更新说明在「关于与更新」中持续可见，常态不反复弹窗。

| 状态 | 界面动作 |
| --- | --- |
| 已是最新 | 显示当前版本、构建号和渠道；可手动检查 |
| 发现更新 | 查看更新内容、下载 |
| 下载中 | 显示进度，支持取消或稍后 |
| 已准备好 | 重启更新、稍后 |
| 有任务运行 | 任务结束后更新，并能查看运行内容 |
| 更新失败 | 保留可用版本，显示可理解原因与重试入口 |

实现复用现有 Rust 下载、包校验与替换能力，并补齐以下边界：

1. 识别 Flutter 的 `DESKTOP.json`；产品、平台、架构、安装方式、版本、构建号、渠道和客户端/Host 兼容范围共同决定更新资格。Flutter、Web core、官方客户端不得交叉选包。
2. 稳定、预览、本地开发渠道分别处理；同版本不同本地构建不能仅靠 SemVer 比较。官方客户端当前安装配置的 `nightly` 更新源属于官方产品，不作为本地 Flutter 版的更新地址。
3. 下载和替换在独立 helper 中执行；沿用文件大小、路径及 SHA256 校验，发行清单增加可信签名校验。
4. 安装前先保存草稿，协调客户端退出；Host 升级需要暂停接收新任务并核对会话、终端、后台作业和调度状态。协议兼容的客户端单独更新可保留 Host。
5. 修正安装器直接强制停止 bundled Host 的行为。进程检查、等待和替换组成同一更新会话，避免检查为空后又启动新任务的竞态。
6. 替换后验证启动和协议就绪；启动失败恢复旧版本。会话、凭据、偏好和用户文件不随应用目录回滚。

首阶段提供可靠的一键更新与失败恢复；后续增加后台预下载、断点续传、退出时安装和忽略单个版本。完整包发布、Windows 安装包和校验清单已有 CI 基础，可直接扩展。

## 实施顺序与验收

| 优先级 | 范围 | 验收结果 |
| --- | --- | --- |
| P0 | 独立项目任务收口 | 入口、工具、自动上下文同时退役，已有文件保留 |
| P0 | 主导航与统计栏 | 保留五项顶部导航；三类统计入口；大字号与窄窗无溢出 |
| P0 | 登录账号显示 | 设置直达保留；登录摘要、空状态、多账号及失效账号清楚可辨 |
| 后续专项 | Flutter 更新闭环 | 正确选包、草稿保存、任务延后、兼容校验、恢复旧版本 |
| 后续专项 | 更新便利性与发行完善 | 后台下载、断点续传、取消重试和平台正式签名 |
