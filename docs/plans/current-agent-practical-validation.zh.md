# 现有单 Agent 多轮实战与交互可靠性验收

## 范围和顺序

优先验证当前运行版的单 Agent 能力和用户交互。团队编排实现与团队实战暂不执行；已有团队方案保留为后续目标。

先记录现状，再复现问题，修复后复验原场景，并完成同一项目的后续任务。运行时错误、用户操作错误、提供方故障和环境缺项分别归类，不以自动测试数量代替项目完成。

## 项目与执行轮次

测试项目和辅助脚本位于独立操作目录；正式测试方案和验收报告保存在项目目录。使用现有可用的单模型路由，不调用团队或子代理，不修改真实业务项目。

| 阶段 | 内容 | 通过条件 |
| --- | --- | --- |
| A | 草稿与输入基线 | 未发送文字不会自行消失；中文组合输入、粘贴、换行、焦点移动正常 |
| B | 5 轮小型应用实战 | 创建应用→增加功能→变更要求→修错→最终验收；产物可运行且独立测试通过 |
| C | 发送与续聊 | 发出的内容出现在对应会话；失败保留或明确恢复草稿；停止后可再次输入、发送和完成任务 |
| D | 当前 Agent 访问另一工作区的真实文件 | 分别验证读取、写入、搜索、命令和子进程；识别执行范围外访问，不能只返回笼统错误 |
| E | 执行过程中的越界审批 | 符合审批策略的操作出现明确审批；未批准不能执行；批准只对应所示调用；拒绝、取消后能继续合理任务 |
| F | 断线、刷新和重启 | 明确区分已接收与未接收请求，避免静默丢消息、重复发送和卡死输入状态 |
| G | 修复复验 | 每个固定故障场景至少连续通过三轮，并继续完成原项目任务 |

## 输入消失的观测点

1. 输入前后的 textarea.value、输入阶段、draftRev、disabled、readOnly 和焦点元素。
2. 输入法 compositionstart/compositionend、粘贴、选择范围和 Enter／Ctrl+Enter 行为。
3. 会话切换、工作区切换、设置和模型弹层、审批处理、后台会话通知与自动刷新。
4. 发送请求的发起、服务器接收、消息持久化、客户端确认与清理草稿时序。
5. 发送期间继续输入新内容、相同文本再次输入、请求失败／取消和迟到确认。
6. 草稿持久化、组件卸载／重挂载、连接恢复和多页签行为。

任何一次文字减少都应对应可解释的用户编辑或已确认的提交；旧请求的完成不得清除后来输入的内容。

重点复现“已经输入并点击发送，但没有正常响应或没有进入对话”。工作区切换仅为补充交互回归，不能替代执行时跨目录审批。

## 审批与文件检查

只使用测试文件验证越界访问。记录发起会话、源工作区、目标工作区、工具调用标识、审批标识、目标路径和处理动作，并保存处理前后的文件哈希。

先以普通项目要求触发访问，观察 Agent 和框架能否自然识别审批需求；再覆盖明确提出审批的任务。包括读取另一目录的配置、从另一项目引用数据、写入交付目录、PowerShell／终端访问和启动外部工具。自动审批策略明确拒绝的场景应解释限制；可申请单次授权的场景应提供可操作的请求，不能静默降级或不断重试同一失败。

- 批准前，目标文件内容必须保持不变。
- 拒绝或取消后，工具不得执行或换路径绕过。
- 切换工作区后，审批卡片仍明确展示原始归属，不能审批到错误会话。
- 一次批准不扩大其他会话、其他成员或后续调用的权限。
- 审批结束、超时和执行失败后，输入框必须恢复可用，后续任务能够继续。

## 成功与缺陷记录

每轮记录任务目标、实际模型路由、请求与会话标识、关键工具结果、产物路径、独立验收结果和后续输入状态。真实模型调用与模拟网络故障分别标记。

缺陷记录包含复现步骤、实际和预期行为、最小证据、严重度、根因、修复位置与复验结果。不能输入、输入丢失、审批归属错误、未经批准写入和错误地报告任务完成均为阻断项。

未能完成的案例保留明确原因；余额、额度、网络或外部服务失败不计为框架验收通过，也不能替代框架故障排查。
