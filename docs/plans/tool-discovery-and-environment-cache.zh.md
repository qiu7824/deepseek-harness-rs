# 工具发现与运行环境能力管理

状态：已实施并完成 Windows 本机回归。工具发现、环境能力缓存、执行配置、统一执行上下文和失败恢复已接入运行时；正式跨平台发行仍以发布工作流的对应平台门禁为准。

## 目标

减少重复工具搜索、本机程序定位和无关参数声明，保持工具可发现性、会话恢复能力与执行权限边界。采用核心工具直接暴露、扩展目录渐进披露、精确名称加载、会话状态持久化和宿主环境能力缓存。

完整实施契约集中在 [工具发现、运行环境与执行可靠性统一修复方案](unified-environment-execution-repair.zh.md)，包含本文的工具目录、自动发现、会话恢复、环境按需探测、缓存失效、配置和验收要求，并扩展用户环境选择、沙箱验证和执行可靠性。本文件保留为基础设计记录。

## 工具目录

- 原始注册表仍是唯一执行权限依据；发现状态只决定模型展示，不授予权限。
- 小目录保留直接调用；MCP 工具默认延迟加载，大目录中非核心工具转入检索目录。
- `tool_search` 按名称、来源和描述进行本地检索，返回完整参数并激活匹配工具，避免必须经历搜索、描述、调用三轮。
- `tool_describe` 支持已知名称直接加载和显式释放；搜索无结果时返回可用来源，不能把词汇不匹配报告为能力不存在。
- 清单在固定字符预算内按来源降级：简述、名称、来源计数。截断保持 UTF-8 边界，并明确省略数量。
- 核心工具与发现入口保持常驻；已加载工具不按每轮关键词自动淘汰。
- 每次装配和执行都重新应用作用域限制，工具卸载立即生效。参数发生变化时按当前定义重新加载。

## 会话与上下文

- 加载结果以版本化非表面事件保存；仅接受宿主产生的结构化事件，不解析聊天文字作为状态。
- 恢复、分叉和上下文压缩后，从会话状态恢复工具名称及声明摘要，并与当前注册表核对。
- 限制会话缓存数量、恢复扫描长度、已加载数量和参数总字节；达到限制时明确说明并允许释放旧工具。
- 通用模型采用普通 function schema，避免依赖某一家提供方专属协议。工具集变化会使 schema 前缀缓存失效一次；稳定后复用，不宣称等价于 Responses 的追加式工具加载。
- 代码模式保持现有执行边界与完整工具绑定；发现入口也可通过 `run_code` 调用。

## 本机环境能力

- 宿主提供 `environment_probe`，使用固定能力目录，不执行模型提供的任意探测脚本。
- 能力包括 Python、Node、Git、ripgrep、PowerShell、FFmpeg 与 WPS 安装位置；程序可定位和实际可运行分别记录。
- 首次按需检查，后续复用；缓存记录环境指纹、程序文件身份、检查时间、状态、版本和受限错误信息。
- 状态区分可用、仅定位、缺失、权限不足、超时及错误；失败结果短期缓存，未知不等于缺失。
- 同一缓存项并发请求合并；持久缓存有版本和大小上限，损坏后重新检查，不影响会话启动。
- 环境变量、程序文件或配置变化、TTL 到期及显式刷新会使缓存失效。
- 自动上下文只提供有效缓存摘要及明确配置的路径，不启动全盘扫描，也不每轮执行外部进程。
- 主机诊断不证明某个沙箱或远程环境能执行；实际任务仍通过原有 Shell、文件与审批链路。

## 配置与运行

- 配置保存在数据目录的 `tool-discovery.json`；缺省采用有界自动模式，`enabled: false` 可恢复全量展示。
- 环境缓存保存在宿主缓存目录，不写入任务工作区，不记录密钥和完整环境变量。
- 提供清晰的搜索命中、已加载数、声明字节数、缓存命中和探测时间，支持比较总延迟和模型调用数。

## 验收

1. 核心工具立即可用；扩展工具搜索一次后直接调用，连续轮次无需重复搜索。
2. 精确名称、中文描述、零命中及超大目录均有可恢复路径。
3. 会话恢复、分叉、压缩、注册更新与卸载不留下越权或过期 schema。
4. 父子作用域、工具限制和现有审批链路不被发现入口绕过。
5. 已加载预算、清单预算、缓存数量和恢复扫描均有确定上限。
6. 环境探测缓存命中不启动进程；同项并发只执行一次；程序变化和 TTL 失效后重新检测。
7. 缺失、超时、权限错误和损坏缓存有明确结果；取消能停止探测进程。
8. 运行工具运行时、会话存储、Host 环境探测及集成回归，核对现有未提交修改不被覆盖。
