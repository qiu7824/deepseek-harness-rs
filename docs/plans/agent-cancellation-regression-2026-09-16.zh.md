日期：2026-09-16。验证环境：Windows、本地隔离 Host、可控模型服务。真实模型调用数为零。

## 已复现故障

### 已取消的成员消息重试超时

复现顺序：主对话和成员执行中分别加入待处理消息，停止全部执行，重试原始请求标识。主对话正确返回 `cancelled`；成员的 `subagent.prompt` 超时。两个独立隔离运行均复现。

堆栈定位到 `schedule` 的异步初始化：成员上下文已进入释放阶段，延迟的初始化仍调用 `register_schedule_tools`，继而在 `Context::effect` 触发 `cannot create effect on inactive context`。外层效果初始化异常退出，未标记初始化结束，清理过程一直等待 `setup_done`，因此消息请求无法返回。

候选修复：

- 定时任务模块只挂载主智能体，跳过标记为 `subagent` 的成员上下文。
- 效果初始化使用析构守卫发布完成信号，即使初始化异常或 Future 被丢弃，也会释放清理等待；异常诊断仍保留。
- 成员重新接收工作时，在唤醒前恢复结果通知标记，避免快速完成时错过结果。
- 隔离检查记录失败时的方法名、请求标识及 Rust 堆栈，区分主对话与成员的恢复阶段。

## 实际界面检查

- 协作面板按 760 像素上限响应式显示，创建任务和成员的表单默认收起。
- 单人模式明确显示临时子代理；关闭团队功能并保存后，既有子代理目录与独立记录仍可打开。
- 设置页曾调用缺少 `sessionId` 的 `session.models`，实际返回 `invalid payload`。改用现有 `/task-models/describe` 全局目录后，角色模型列表正常显示；DOM 回归检查覆盖该请求协议。
- 成员上下文空闲释放后，原前端会因父会话不在线显示只读。候选实现增加 `parentResumable` 提示，浏览保持只读查询，明确发送时恢复原主会话并通过其子代理运行时提交；提交期间保留主会话的生命周期锁。
- 实际页面连续完成三轮成员发送，覆盖按钮、中文多行与回车、刷新后发送。三条用户消息均只持久化一次，均收到完成回复，原模型、输出上限与工具限制保持不变。
- 浏览器协议解析原先丢弃新增的 `parentResumable` 与 `running` 字段，导致后台恢复成功后仍显示只读或可能残留运行状态。生产解析器已同步，回归覆盖旧版响应和错误类型。

冷恢复证据位于 `D:\codex操作目录\dsh-team-goal-20260916\member-cold-resume\run-1789554952918982200`：控制夹具 16 项通过，`ui-member-history.json` 与 `ui-member-continuation-evidence.json` 记录三轮实际页面发送。当前冷恢复支持普通主会话的直接子代理；父级本身是已释放子代理的更深层级仍需单独验证和完善。一次性子代理继续保持只读。
