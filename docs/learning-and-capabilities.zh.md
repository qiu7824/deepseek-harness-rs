# 技能、工具与经验记忆

## 设置中的能力管理

“设置 → 技能与 MCP”提供技能搜索、内容查看、创建、导入、编辑、删除和启用开关。停用技能后，技能目录和技能调用都会排除该技能。受管理的技能保存在数据根的 `capabilities/skills` 目录，配置保存在 `capabilities/settings.json`。

MCP 支持标准输入输出和 HTTP 连接。服务器可以保存连接参数、启用、停用、测试和删除；测试会完成协议握手并读取工具列表。服务器停用时会断开连接并撤销其工具。凭据字段不会随服务器列表返回到浏览器。

技能和 MCP 设置在本机界面管理。MCP 程序以本机进程运行，使用前应确认程序及服务器可信。

## 技能动态加载

每次模型步骤开始前更新技能名称和摘要目录；只有模型调用 `skill` 或用户使用 `/技能名` 时才读取正文。未使用的技能正文不会全部进入上下文。

已经加载的技能会按正文内容指纹检查变化。界面保存或直接修改文件后，后续请求会收到一次最新正文通知；停用、删除或无法重新验证时，会收到明确的停用通知。冷启动恢复会从有来源的技能记录重建状态。旧工具结果保留在历史中，新的有效状态明确替代旧技能指令，工具权限继续独立校验。

动态状态最多跟踪 16 个技能，单次请求最多更新 4 份正文、128 KiB，检查时间最多 2 秒；文件正文读取上限为 1 MiB。超过预算时会提示按需重新加载，避免重复或无限制地注入正文。

## 审批交互

审批沿用原版对话内审批卡。卡片显示原因、命令或目标文件路径；文件读取、写入前的授权由 Rust Host 执行。拒绝不会执行对应操作，允许一次不保存许可，可记忆的目录写入只覆盖同一目录，其他目录和子目录仍会询问；敏感文件审批不支持记忆。

审批等待期间重连会恢复原请求，已取消或结束的请求不能再次批准。默认等待 30 秒，超时按“安全盾 → 无人确认”策略处理；默认策略为拒绝。可在同页调整等待时间。

## 减少重复错误

“记忆与上下文”包含自动经验记录与手动记忆。经验保存在本机数据目录，模型参数不会因一次对话自动改变。

自动记录覆盖工具失败、带结构化错误码的模型请求失败，以及用户对回复的负面反馈。相同工作目录、工具和错误类别会合并计数，并保留发生时间与当时使用的模型；模型标识仅用于追溯，不表示错误由模型造成。原始工具输出、调用参数和反馈正文不会复制到经验账本。

可复用经验首先处于“待验证”状态。参数校验、写入前观察和编辑匹配不唯一等已知错误，只有在同一会话、同一工具和匹配目标上恢复成功后，才会自动成为“已验证”经验，无需逐条手动确认。未知错误与负面反馈在证据不足时不自动形成长期规则，用户可以补充已验证的方法；成功回复或单次点赞不会证明某个错误已解决。

人工接管、审批取消或超时、断线、连接繁忙和截图换代等运行状态不作为新的经验失败记录。旧记录保留可查，但不进入长期上下文，也不要求确认修正建议。服务请求失败单独作为诊断显示；参数校验失败仍须核对调用和校验器实现。已确认的 Agent 缺陷应修复代码并补回归，不能用要求用户记忆来代替修复。

后续请求会在有限预算内选取当前工作目录的已验证、启用经验。通用工具经验可供不同模型复用；供应商错误和回复反馈只适用于对应供应商与模型。上下文页可以预览下一次请求的候选经验，预览本身不会增加复用次数。执行前匹配记录只统计实际加入当前请求上下文的经验，不能据此断言模型一定遵循了建议。

尚未恢复运行的历史会话可以只读预览经验，并明确标注最近请求的工具快照。历史读取有数量与时间限制；缺少工具快照时显示尚不能判断，实际执行前会重新读取当前工具目录。

工具执行仍按当前参数 schema、文件观察状态、权限和运行依赖进行校验。即使经验已经确认，过时或无效的调用也不能绕过这些检查。参数不符合当前 schema 时，工具主体不会执行。

自动经验提供总开关、搜索、逐项启用、确认和删除。停用后不再自动记录或注入，已保存数据保留；逐项停用只影响该项的后续复用。写入队列和存储都有上限，保存失败会在界面显示，原有数据不会被成功提示掩盖。

手动记忆用于维护偏好、已知错误、项目知识及操作约束。

已知错误适合记录四项内容：触发条件、已验证的错误原因、正确做法、完成后如何验证。例如，某个接口必须使用特定参数时，应记录接口与适用范围、失败响应、有效参数和回归用例，避免只写“以后不要犯错”。

`default` 作用域中的启用记忆适用于所有预设，特定预设的记忆只应用于相应预设。已知错误和操作约束在有限记忆预算内优先保留。开关会影响后续上下文组装；删除或停用错误经验后不再注入。机密凭据不应写入记忆正文。

稳定的项目规则适合保存在项目指令中，可重复的工作步骤适合整理成技能，确定的功能缺陷适合加入自动化回归测试。记忆能够降低重复错误概率，测试与工具校验负责验证实际结果。

Codex 可以在任务开始时读取全局和项目层级的 `AGENTS.md`，以持久化规则统一任务行为；启用本地记忆后，还可在会话空闲后后台整理可用经验。必要规则仍应保存在项目指令或文档中。详见 [OpenAI 记忆说明](https://learn.chatgpt.com/docs/customization/memories?surface=app)和 [AGENTS.md 说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。

## 代码执行运行环境

Rust Host、标准会话、Rust 原生工具和预构建的 Web 界面无需 Node.js。PTC 代码模式使用 JavaScript / TypeScript 编排工具调用，必须具备兼容的 Node.js 运行环境；部分 MCP 服务器和项目构建工具也有自己的依赖。

“目录与运行环境”显示实际使用的 Node 路径、版本、权限模型、TypeScript 和工作线程能力。PTC 预设激活前会检查这些能力；依赖缺失或不兼容时，会在请求模型之前提示检查环境或选择标准模式。检测不会下载或安装软件。

## 上下文与模型显示

会话的“上下文”标签位于“代码图谱”旁，保留会话、模型、提供商、消息数、上下文容量、输入输出及缓存 token 等信息，同时显示占用比例和内容组成。内容组成按当前上下文估算，累计用量按提供商报告汇总；未报告的成本或推理用量显示为未提供。

模型显示开关控制模型选择器中的候选项。已有会话仍保留原模型记录。推理等级优先读取模型目录元数据，其次使用已知具体型号的能力；未知型号保留自动模式，避免向提供商发送不支持的等级。


## 诊断原因与核对证据

自动经验区分可复用规则和运行诊断。诊断核对结果持久保存原因、状态、结论与原始事件或回归证据定位，可按 Agent 实现、调用或业务脚本、环境、提供方、任务状态、混合原因与证据不足筛选。出现新事件后，旧核对结果明确标为需要重新核对；核对不会将诊断提升为长期指令。已验证修复的条目可按修订删除，混合原因和证据缺失记录保留。

执行环境的模型快照保留实际程序路径、权限、后端与配置身份；探针时间戳、检查 ID 和缓存命中信息只保留在诊断接口中，避免正常检查使整份上下文反复更新。权限或程序身份发生变化时仍更新模型快照。

## Office 与 PDF 视觉检查

Windows 的 `office_render` 使用 WPS 转换 DOCX、XLSX、PPTX，再使用 Windows 原生 PDF 渲染器生成页面图像；也可直接读取已有 PDF。此通道无需 Python、LibreOffice 或 ffmpeg。输入限定当前工作区，转换使用副本，PDF 保存为任务所有的候选资源，可在验证后通过 `workspace_scratch` 提交到目标位置。

`pages` 使用从 1 开始的页码，单次最多 12 页，默认第一页。结果包含总页数、实际页面图像与来源摘要；应检查全部相关页面，有单独视觉模型时可将返回的图像交给 `consult_model`。`visualReviewComplete: false` 表示渲染本身没有替代视觉判断。包结构、XML 和关键词校验不能证明分页、字体、表格或裁切正确。

WPS COM 使用固定的宿主文档通道；普通沙箱命令仍遵守独立账户或受限令牌权限。程序以非零状态退出，只能证明它启动后失败；无标准输出或标准错误时不能据此断言程序没有启动、依赖没有安装或沙箱拒绝。需要新项目初始化时，`environment_initialize` 只准备当前工作区并保留已选沙箱和网络策略。

## 语音输入

按住语音按钮或空格键开始输入，松开结束。临时识别结果立即更新草稿，最终结果替换临时文本，不重复追加。切换任务、取消或手动修改草稿会防止旧识别结果覆盖新内容。浏览器语音服务和网络仍影响首字延迟；权限及服务错误直接显示。

## 参考机制

[Hermes 的持久记忆](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)采用有预算的会话初始快照，历史检索按需调用，避免将日志整体塞进长期记忆。[Codex 本地记忆](https://learn.chatgpt.com/docs/customization/memories?surface=app)在适用会话空闲后后台整理有用内容；强制规则应保存在 [AGENTS.md 或项目文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。本软件将诊断、已验证经验、稳定规则与实际工具能力分别维护，保留当前权限校验。
