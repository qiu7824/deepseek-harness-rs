# DeepSeek Harness 上下文与能力差距调查

调查日期：2026-09-15，证据复核截至 03:23（UTC+8）  
代码基线：`20fd6e9af713eda27dc3f87a23d46fb0a59652b8`，同时检查当前工作树。  
调查对象：标准模式的指令、技能、工具、上下文管理及其与 Codex 实际会话的差异。

## 1. 结论与决策顺序

Harness 已有文件与终端工具、技能按需加载、记忆、压缩、计划、目标、子代理、浏览器、桌面控制、MCP 和交付呈现等基础设施。输入更短不等于缺少这些基础设施，也不能直接证明任务质量更低。

最明确的缺口是：**个人规则没有进入标准会话，常用专业技能没有接入；上下文来源和后台模型用量的解释还不够细。** 同时，标准模式仍常驻了与普通任务无关的应用开发说明，存在继续精简的空间。

建议分四类处理：

| 类别 | 建议处理项 |
| --- | --- |
| 优先完善 | 个人规则接入及生效诊断；WPS/Office/PDF 等常用工作流；交付验收的简短默认约定；按来源解释上下文和统计辅助调用 |
| 接入能力增长前完善 | 技能目录总预算、遗漏提示及检索入口；工具按任务暴露与能力发现；规则截断和覆盖诊断 |
| 按使用场景完善 | 桌面 UIA 与持久操作会话；高级应用集成；技能制作、视频、研究和交互展示工作流 |
| 不需要照搬 | Codex 专用协议与指令；未安装插件全量目录；所有专业技能全文常驻；全部文风限制；每项任务强制子代理和目标循环 |

不建议以“把输入补到 26k token”为目标。应以相同任务的结果合格率、总用量、修正次数和执行时间作为验收指标。

## 4. 优先完善的缺口

### 4.1 个人规则没有进入标准会话：配置接入缺口

**确认事实：** 原始 Harness 首轮没有 AGENTS.md 来源消息。当前数据根的 `AGENTS.md` 不存在，样本工作目录 `E:/python/test` 的 `AGENTS.md` 也不存在；Codex 全局 `C:/Users/xs/.codex/AGENTS.md` 存在，并且比较会话实际带入了对应规则。

Harness 并非没有指令加载器。`agent-instructions` 会读取 `$DSH_HOME/AGENTS.md`、项目根到当前目录之间的 `AGENTS.md`、`CLAUDE.md` 及 local 变体，并在文件发生变化后建立新的有效基线。它不会默认读取 Codex 私有目录中的全局规则。

**实际影响：** WPS 优先、临时操作目录、过程沟通、正式产物内容隔离等稳定偏好，不能仅因为在 Codex 中设置过，就假定标准 Harness 同样知道。样本有少量长期记忆，不代表完整规则已同步。

**建议：** 设置中增加个人规则编辑和受控导入，列明来源、作用域、当前是否生效、覆盖关系及遗漏原因。导入后以 Harness 自己的配置为准，避免后台无提示地跟随另一应用变化。

**验收：** 新会话、恢复、切换工作目录、规则修改、规则删除都能显示正确有效基线；同一规则不在每个步骤重复追加。明确用户当轮指令优先于冲突的文件指导。

优先级：**P1，立即值得完善。** 主要是配置与诊断，不需要扩写整个系统提示。

### 4.2 常用专业技能未接入：内容与运行依赖缺口

**确认事实：** 样本技能目录只有 `dsh-badge`。当前 `skills` 和 `capabilities/skills` 目录为空，`~/.agents/skills` 不存在。技能发现器支持项目、用户、自定义及打包技能根，但不自动扫描全部 Codex 插件缓存。

**实际影响：** 即使模型能通过 Shell 操作文件，也缺少稳定的表格保真、Word 分节、PDF 页面核对、公式重算和正式模板交付流程。缺少的是可靠工作流和依赖接通，不是模型完全不能生成这些文件。

**建议：** 优先接入 WPS Excel 转 Word、Word、PDF、表格和演示文稿工作流。逐项核对脚本路径、运行平台、字体、工具名称、附件输出、页面渲染及 WPS 调用；不能直接把依赖 Codex 专用工具或容器的技能原文复制后就宣称可用。

**验收：** 各技能至少一个真实文件任务；对表格分页、合并单元格、公式结果、页数、中文字体、附件打开和可编辑性检查。Excel/Word 制作遵守 WPS 约束，不能以 LibreOffice 替代验收。

优先级：**P1，高使用频率能力先接入。** 技能正文仍按需加载。

### 4.3 默认任务执行与交付验收约定偏少：指导缺口

**确认事实：** 原样本系统提示主要是工具选择、临时文件、后台任务、网页和目标工具说明，没有看到与 Codex 长篇行为要求等量的执行与验收约定。现有回复完整性机制可以处理空答复、流截断和明确中间状态，但协议层正常结束不证明用户任务已完成。

**建议保留的短规则：**

- 对清晰的执行请求推进至可交付状态，避免只回答“可以”。
- 先检查可获得的事实；只有缺少用户独有信息时才提问。
- 遵守已给出的授权与约束，保留用户未提交的工作。
- 修改后完成与风险相称的核验；没有验证的部分明确说明。
- 将已完成、部分完成、受阻、取消区分开，不能用工具成功代替目标完成。
- 交付正式文件并确认可访问，结论说明关键限制。

这些是行为指导，不能保证模型永不遗漏；重要边界继续由工具与运行时执行。样本中的询问截图在两边都出现，不能用这个例子证明 Harness 普遍更容易提前停止。

优先级：**P1，小而稳定的默认约定，配合任务评测。** 不照搬 21k 字符文风与过程规定。

### 4.4 用量解释与辅助调用统计：可观测性缺口

**已有：** `token-meter` 有提供方用量累计、缓存信息和上下文组成投影，不需要重做一个基本计数器。

**确认限制：**

- 上下文组成只分 `systemTokens`、`toolsTokens`、`messageTokens`，不能直接解释某个技能、某个工具或某份规则占了多少。
- 分项估算采用固定 4 字符/token 启发式；中文、代码、JSON、图片和提供方封装差异会影响准确性。运行计量还有提供方用量锚点及图片定价路径，不能把所有显示值都称为粗估。
- 标题生成请求有 `purpose: session-title`，但标题逻辑没有把它的 Usage 写入该会话现有累计投影所消费的事件。该投影主要读取 `assistant/chunk` 和 `assistant/message`。

**建议：** 为每次模型调用增加统一调用 ID、用途、模型、实际输入/输出/缓存及未知状态。区分主任务、标题、摘要、子代理和其他模型工具；父子调用不得重复汇总。上下文另提供按来源组成、估算方法、原始字节/字符量、总用量实测值和差异解释。

**验收：** 标题失败、重试、取消、有缓存、摘要、子代理均能对账；没有报告用量应显示未知，不能当作 0。分项估算明确标注，不能伪装成精确账单。

优先级：**P1，直接影响省 token 判断的可信度。**

## 5. 随能力增长需要完善的部分

### 5.1 技能目录总预算与发现路径

已有单条描述截断、目录摘要变化检测、正文按需加载、已加载技能热更新和停用通知。当前目录装配代码把所有可调用技能映射为条目，单条描述默认限制为 500；该装配路径未见面向模型上下文容量的目录总预算。

增加 20 项技能可以接受，但增长到大量技能时，仅限制每条长度仍会整体膨胀。建议总预算、优先级、可见遗漏提示和按需检索并存；用户明确点名的技能必须有可达加载路径，不能静默丢失。

OpenAI 官方技能说明同样采用摘要目录加正文按需加载，并描述了目录预算与遗漏提醒。这是可借鉴的设计，而不是复制其具体阈值的必要理由。[官方技能说明](https://learn.chatgpt.com/docs/build-skills)

### 5.2 工具按任务暴露，而不是删除工具

标准模式会给模型完整呈现作用域内可见工具，已有 allow/deny 限制与代码调用模式。代码模式把直接入口收敛为 `run_code`，但底层工具使用声明仍需提供；“只剩一个入口”不代表全部 schema 成本消失。

建议先按稳定预设或能力组管理：基础读写与查找、Office、桌面与浏览器、代码分析、自动化、外部服务。随着规模增长，再增加按需工具发现和声明加载，兼顾缓存稳定性与工具可发现性。不要根据一句关键词永久隐藏后续可能需要的工具。

本次未在标准模式装配路径发现等价于通用 `tool_search` 的按需 schema 发现流程。MCP 已能连接和加载工具；“已支持 MCP”与“已支持大目录按需发现”是不同问题。

验收应检查：闲聊输入减少、复杂任务仍能找到能力、切换模式不越权、已停用工具无法执行、缓存和总请求次数没有抵消收益。

### 5.3 规则覆盖、截断和子目录行为

当前规则发现按会话当前目录读取项目链。编辑更深目录的文件不会仅因目标路径变深而自动重建目录链。应明确是否支持目标文件范围规则，并在进入子树时发现，不能一开始递归加载整个仓库所有 AGENTS.md。

还有三项明确差异：

- 当前候选名没有 `AGENTS.override.md`；如果需要兼容 Codex 项目，应明确支持或明确提示不支持。
- 同目录的 AGENTS/CLAUDE/local 文件可能一起合并，需把优先级做成清晰约定。
- `render_baseline` 超限会保留靠后的文件或截取最后一个正文；输出中未见显式截断标记，前部全局约束可能被省略。

建议显示加载、覆盖、未读取、超限、删除和截断状态，并保证被截断后不冒充完整规则。Codex 的 override 优先级及每目录选取方式可作兼容参考，无须放弃 Harness 对 CLAUDE/local 的既有支持。[官方 AGENTS.md 说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

### 5.4 清理无关常驻提示

原始 4,957 字符系统提示中，Web GUI/HMR/构建说明占 992 字符，临时文件和诊断指导占 1,304 字符，目标工具指导占 734 字符。它们不是重复两次发送；这是同一提示的独立段落。

Web GUI 段含 `apps/web`、`pnpm run dev:web` 和构建约定，在 `E:/python/test` 的桌面右键问题上也进入模型。当前 Host 同样无条件注册 `app:web-surface` 段。应保留简短的当前应用身份及“没有隐式画面”，把应用开发细节移至维护 Harness 时才加载的指导，并验证路径和命令对应 Rust 版本。

临时文件保护是必要规则，可以保留短默认约定，把 prepare_copy/promote 等详细操作放到相关工具或技能。目标工具保留启动与完成边界，其余流程按使用场景加载。

这是删除无关输入的机会，不是能力缺口。节省量需要在真实请求中复测，不能将字符数直接当作 token 收益。

## 7. 桌面、浏览器与专业运行环境

Harness 已有原生桌面截图和输入执行器、浏览器适配器、标签页与上传、UU 远程控制及取消/生命周期基础。原样本中有 `computer_use`，但未实际调用，因此不能据此推断当时桌面控制一定可用或不可用。

当前 `crates/computer-use` 未检索到 `IUIAutomation`、`UIAutomation` 或控件树实现标记；已有 Computer Use 规划也将 Windows UIA、应用级授权和专用持久 JavaScript 会话列为待实施内容。它们是更可靠桌面操作的工程能力，增加提示词不能替代。

| 场景 | 是否值得完善 | 边界 |
| --- | --- | --- |
| WPS、系统设置等频繁桌面操作 | 值得，优先提高目标窗口识别、控件定位、观察与动作校验 | 必须真机验收，不能只检查 schema |
| 浏览器批量操作 | 在现有 CDP/标签页能力上完善状态与结果验证 | 有浏览器支持不代表所有登录网站可用 |
| PDF、Word、表格和 PPT 文件处理 | 优先建立运行依赖清单与可执行工作流 | 运行时、字体、渲染、重算必须实际可用 |
| 图像和视频生成 | 已有图像工具基础，按用途接入生产工作流 | 账号能力、引用图片及产物输出要单独核验 |
| Codex 专用侧栏、审查链接、语音页面状态 | 不按接口原样移植 | 用 Harness 自己的 UI/附件/任务语义实现对应需要 |

## 8. 对 20 项 Codex 技能的取舍

这里判断的是工作流价值，不代表对应 Codex 工具和托管服务能直接在 Harness 调用。

| 技能 | 建议 | 实施方式 |
| --- | --- | --- |
| convert-excel-to-word-fidelity | 优先接入 | 改为 Harness 可用的 WPS、路径与输出流程 |
| documents:documents | 优先接入 | 保留编辑与页面核对原则，适配本机 WPS 运行环境 |
| pdf:pdf | 优先接入 | 页面渲染、文本提取、正式文件验收 |

## 9. 建议的上下文分层

| 层 | 内容 | 加载时机 |
| --- | --- | --- |
| 固定核心 | 精简执行约定、证据与交付原则、稳定工具约束 | 每个请求的稳定前缀 |
| 当前事实 | 模型、工作目录、权限、语言、当前应用身份 | 按当前状态组装并替换旧快照 |
| 个人与项目规则 | 明确来源和优先级的有效 AGENTS/偏好 | 会话开始、作用域变化、内容变化 |
| 能力索引 | 有总预算的技能摘要及发现入口 | 会话能力变化时更新 |
| 任务工作流 | WPS、PDF、视频、网页、代码维护等完整指导 | 任务触发或用户点名时 |
| 执行证据 | 必要工具结果、引用、截图、测试摘要 | 执行后保留相关部分 |
| 历史与记忆 | 当前任务相关历史与已验证经验 | 有预算选择；压缩后保留约束和未完成项 |

权限校验、参数校验、文件版本冲突、取消、目标身份与资源释放继续由运行时执行。不能为了少 token 删除这些实现，也不能依赖更长提示替代它们。

## 10. 实施批次与验收矩阵

### 第一批：规则与常用工作流

接入个人规则，提供有效来源视图；增加简短执行验收约定；适配 WPS/Word/PDF/表格工作流。各能力有真实文件任务通过后才标为可用。

### 第二批：计量与精简

纳入标题等辅助调用；按来源解释上下文；清理全局 HMR 开发段；加入技能目录总预算和遗漏提示。工具按组暴露先做实验，不直接全局切换。

### 第三批：复杂自动化

按实际桌面与视频任务完善 UIA、持久会话、语义操作和可复用模板，接入需要的外部服务。

| 评测任务 | 核验重点 |
| --- | --- |
| 普通问答与澄清 | 不加载无关专业正文，不新增不必要工具往返 |
| 代码修改 | 保留已有改动、执行必要验证、交付可核对结果 |
| 多目录代码修改 | 作用域指令和覆盖关系正确，遗漏可见 |
| WPS 表单制作 | 合并格、边框、分页、中文字体及编辑性 |
| PDF 图纸/材料信息整理 | 页码与来源对应，采样限制明确，正式内容无过程文字 |
| 长会话恢复 | 用户纠正、未完成目标和关键约束保留 |
| 工具失败恢复 | 不重放错误操作，不把搜索失败当零结果 |
| 桌面/浏览器操作 | 目标与观察一致，操作后复核、取消和人工接管正确 |
| 技能更新/停用 | 新状态替代旧状态，不可继续调用失效能力 |
| 调度与子代理 | 作用域、通知、收尾与总用量正确 |

对每类任务在相同模型、推理等级、权限和初始文件状态下运行多次，比较当前版和候选版；冷缓存与热缓存分开。记录主任务加全部辅助调用的总 token、完成率、用户纠正次数、重试、耗时和产物质量。不能只用一次短问题宣布总体质量或成本优势。
