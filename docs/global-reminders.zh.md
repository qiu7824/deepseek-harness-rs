# 全局提醒

Web 与 Flutter 的设置页提供“全局提醒”，可按会话和状态筛选、搜索、创建、编辑、删除提醒并查看发送记录。提醒始终属于创建时选定的会话；编辑提醒不会改变所属会话。

## 启用与规则

提醒插件默认关闭。开启后，Host 负责计时和投递；关闭客户端窗口后，只要 Host 仍在运行，提醒仍可触发。停用插件保留任务和发送记录，期间可查看或删除任务，创建和编辑需要重新启用。

| 规则 | 时间设置 |
| --- | --- |
| 延迟一次 | 从创建时间起经过指定秒数 |
| 指定时间一次 | 指定日期、时间和 IANA 时区 |
| 固定间隔 | 按固定秒数重复，最短 60 秒 |
| 每天 | 按所选时区的本地时间重复 |
| 每周 | 按所选时区、星期和本地时间重复 |
| Cron | 五字段表达式：分钟、小时、日、月、星期 |

标题去除首尾空白后最多 120 个 UTF-16 单元。日历规则显式保存时区，例如 `Asia/Shanghai`，切换客户端所在时区不会改变原规则。夏令时跳过的本地时间不触发周期提醒，重复出现的本地时间只触发较早一次；一次性任务拒绝不存在的本地时间。

Host 重启或恢复运行后，周期任务仅投递最近一次错过的提醒，不逐条补发历史积压。一次性任务发送后保留为已完成状态，可继续查看发送记录。投递失败的任务保留原到期时间，排除故障后可使用重试入口再次触发检查。

## 编辑与发送记录

编辑使用原始记录校验版本；若其他客户端已修改任务，界面保留草稿并显示冲突，刷新后可重新核对。未改变时间规则的保存不会重新计算相对时间起点。

发送记录确认提醒已经写入会话，模型的执行结果在会话中查看。记录默认保留最近 30 天、最多 200 条；可调整为 1–3650 天和 1–10000 条。修改保留设置不会启用插件，旧记录在下次追加发送记录时按新设置裁剪。

投递至会话与更新任务记录分属两次持久化提交；如果 Host 恰好在两者之间异常退出，恢复后可能再次投递该提醒。

## 会话管理与旧提醒

归档包含活动提醒的会话时，需要确认停止这些提醒；已完成任务的记录保留。永久删除会话时，同时移除该会话及被删除子会话的提醒数据。

旧版本写入会话日志的提醒仍可读取，新任务使用 Host 任务库。旧任务不会自动迁移或继续由旧计时器投递，需要在“全局提醒”中重新创建。
