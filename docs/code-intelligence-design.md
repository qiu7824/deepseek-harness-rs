# Agent 代码智能工具设计

## 目标

代码智能面向 Agent 的定位、理解和修改决策。界面负责检查证据，工具返回可引用的文件位置、关系和不确定性，不输出无法操作的全量图。

## 核心入口

| 入口 | 用途 | 输出上限 |
|---|---|---:|
| `code_context` | 从自然语言、符号或文件定位实现 | 12 个候选，最多 50 个 |
| `code_callers` | 查找直接及递归调用者 | 默认 2 层，最多 4 层 |
| `code_callees` | 查看实现依赖的调用路径 | 默认 2 层，最多 4 层 |
| `code_impact` | 修改前识别受影响入口、测试和配置 | 50 条证据 |
| `code_path` | 查找两个符号间的最短调用链 | 20 跳 |

所有入口接收可选 `path` 范围，默认限制在当前 Workspace。每条结果包含符号、类型、文件、行号、关系、证据来源和置信度。基于同名匹配推导的跨文件调用必须标记为启发式，不能表示为编译器已解析关系。

## 索引与增量

索引分为文件清单、符号、引用和调用四层。文件变更只重建受影响文件及邻接关系；同一 Workspace 的 Web 检查和 Agent 工具共享一个索引实例。索引过程遵守忽略规则、文件数量、单文件大小、总字节、超时和取消上限。

索引状态包括 `ready`、`partial`、`stale` 和 `failed`。部分结果携带未覆盖文件和原因，Agent 可以继续读取具体文件补证。

## Agent 工作流

1. `code_context` 找到候选入口和相关测试。
2. `code_callers` 与 `code_callees` 确认行为边界。
3. Agent 读取候选位置附近的源码。
4. `code_impact` 生成修改前检查清单。
5. 修改完成后以文件变更集再次调用 `code_impact`，核对新增风险。

## 界面

代码图谱页默认显示查询框和证据列表。选择符号后展示局部调用链、受影响文件、测试建议和索引覆盖状态。节点点击直接打开源码位置；全项目拓扑作为诊断视图按需加载，不进入默认路径。

## 验收

- 在 5,000 文件 Workspace 中，首次查询可取消，重复查询复用索引。
- 同名函数显示独立候选和文件位置，不静默合并。
- 修改一个公开入口时，结果覆盖调用者、被调用者、相关测试和配置引用。
- 超过预算时返回部分结果和明确缺口，不返回空白页或伪造完整关系。
- Agent 工具结果在默认上限内可直接用于后续文件读取。
