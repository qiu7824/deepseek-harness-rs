# 模型请求等待与输出速率异常修复方案

## 1. 范围与目标

修复两类问题：模型请求长时间停留在等待状态；输出速率出现约 9000 tok/s 等难以解释的读数。覆盖本机与远端执行、图片输入、模型切换、重试、断线重连和历史记录回放。

交付目标是请求有明确阶段、有界等待、可取消，速率有准确统计口径和执行来源，缺失或不可靠的数据不生成误导性数值。

## 2. 问题一：图片请求长时间等待

### 2.1 已确认事实与诊断边界

- 对应会话先收到 Devin 当日额度耗尽错误，随后切换至 `deepseek-official/deepseek-flash`；前一次额度错误不能直接解释切换后的请求停滞。
- 对应原图已持久化为约 2.2 MB 的会话附件。
- 已检查的会话记录停在 `request/header`、`request/context` 之后，未见该轮模型输出、工具调用或结束事件。这些事件记录本地请求构造，不证明 HTTP 请求已经发出。
- DeepSeek 图片路径先尝试 Files API；单次文件请求默认超时为 120 秒。`resolve_image_file_ids` 的错误在调用方被统一归入 Base64 回退分支，失败原因未在该处保留为可见阶段信息。
- 图片变体读取未传入取消信号；上传锁等待缺少阶段时限；上传后的冗余和过期文件删除位于请求关键路径。
- 通用模型 HTTP 传输设置了连接超时，但等待响应头没有独立期限；错误响应正文读取也需要补充有界等待与取消。
- 流读取默认空闲超时为 300 秒，按收到字节重新计时，不能识别持续心跳却没有有效输出的情况。
- 前端主要根据文字、思考和工具状态显示等待，不能准确区分附件准备、上传、等待响应头等阶段。

120 秒上传超时与约两分钟等待现象相符，但尚未获得该次请求的阶段日志，不能将其认定为唯一根因。

### 2.2 修复设计

#### A. 附件准备与上传

1. 将请求取消信号贯穿附件读取、变体生成、上传锁获取、上传和缓存操作；取消后不得继续执行 Base64 回退或发送模型请求。
2. 为整个附件准备阶段设置总预算，包含锁等待及全部图片处理，避免每张图片独立累加完整超时。
3. 区分没有附件、接口明确不支持、可回退的传输错误、权限拒绝、额度耗尽和取消。只有连接支持内联图片且错误符合回退策略时，才允许转换为 Base64。
4. 记录上传命中缓存、开始、完成、失败及回退事件；错误信息保留阶段和错误类别，不记录凭据和图片正文。
5. 将过期文件清理放入有界后台队列，绑定服务生命周期，保留失败重试记录；清理不阻塞当前模型调用。

#### B. 请求与流式等待

采用分阶段期限，而非对持续输出的整轮任务设置短硬截止。以下为初始配置建议，发布前按真实连接验证：

| 阶段 | 初始预算 | 结束条件 |
| --- | --- | --- |
| 附件准备整体 | 120 秒 | 准备完成、取消或阶段超时 |
| 建立连接 | 10 秒 | 连接成功或失败 |
| 模型 HTTP 发送至响应头 | 60 秒 | 收到响应头、取消或超时；连接时间包含在此预算内 |
| 非成功响应正文读取 | 15 秒 | 正文结束、大小上限、取消或超时 |
| 无有效模型进展 | 180 秒 | 有效进展重置；深度思考连接可配置为 300 秒 |

有效进展包含文字增量、思考增量、工具参数增量及适配器明确识别的实际执行进展。心跳、空字符串和重复状态通知不重置有效进展时钟。服务端不暴露思考进展时，按该连接配置等待预算并准确显示尚无可观测进展。

所有超时返回统一的结构化失败信息，包含 `phase`、`code`、`elapsedMs` 和 `attemptId`。取消与超时释放连接、上传锁和等待任务，当前请求仅产生一个终止结果；正常输出继续保留。

#### C. 阶段事件与界面状态

增加请求阶段事件，至少覆盖附件准备、上传、请求发送、响应头到达、首次有效输出、流式进展、重试等待和终止。事件按会话、轮次、步骤、请求尝试关联，并记录执行实例。

前端显示“准备图片”“上传图片”“等待服务响应”“等待模型输出”“正在思考”“正在生成”等真实阶段。阶段事件只用于运行状态和诊断，不注入模型上下文或最终回答。

停止操作在可取消的异步等待阶段以 1 秒内退出为验收目标。同步图片处理在进入和退出时检查取消，不能声称丢弃异步包装即可中断底层计算。断线重连从后端恢复权威状态，不以浏览器计时器判断请求是否存活。

#### D. 重试与失败分类

复用现有重试框架。额度耗尽、权限拒绝、参数不支持及取消不得自动重试；短暂传输故障只在明确策略下有限重试，并展示次数和倒计时。请求可能已被接收时保留结果不确定状态，不承诺重发无额外计费。工具执行与图像生成不能随模型请求重试而重复执行。

### 2.3 主要改动位置

| 文件或模块 | 改动内容 |
| --- | --- |
| `crates/llm/llm-deepseek/src/lib.rs` | 附件准备预算、错误分类、信号传递、流式有效进展期限 |
| `crates/llm/llm-deepseek/src/files_api.rs` | 文件请求取消、错误保留、清理任务边界 |
| `crates/llm/llm-deepseek/src/transport.rs` | 响应头期限、错误正文期限、传输资源释放 |
| `crates/core/agent-loop/src/agent.rs` 及请求生命周期模块 | 请求尝试标识、阶段事件、单次终止与状态收敛 |
| `crates/llm/llm-retry` | 错误分类与有限重试策略兼容 |

## 3. 问题二：约 9000 tok/s 与速率来源不明确

### 3.1 已确认事实与待验证原因

当前速率主要使用以下公式：

`outputTokens / ((assistantMessageTime - firstTokenTime) / 1000)`

前端 `deriveTurnMetrics` 和后端 `sessionStats` 存在对应实现。已确认的问题是：零时长样本仍可累加输出 token；当它与其他有正时长的样本合并时，分子增加、分母不增加，聚合速率会被抬高。

还需验证以下情况：

- 代理缓冲后集中发送、非流式响应被适配成增量，导致接收时间窗口很短。
- 输出 token 包含未实时传输的思考 token，但计时从首个可见增量才开始，统计范围不匹配。
- 多次重试的 token 与时间没有严格按同一次请求尝试配对。
- 不同电脑、后端实例或历史回放数据在前端缓存和聚合时发生混用。
- 系统时钟调整，或毫秒与秒转换错误。

尚未取得产生约 9000 tok/s 的原始请求事件，不能认定其必然来自其他电脑，也不能单凭数值高就认定统计错误。模型在服务端执行时，该读数通常不代表客户端电脑的推理性能。

### 3.2 修复设计

#### A. 明确统计口径

1. 默认展示“请求平均输出速率”：以同一次请求的供应商输出 token，除以模型请求发送至终止的单调时长；包含该请求的服务等待与思考时间，不包含附件上传和本地工具执行。
2. 该指标反映端到端请求表现，不命名为服务端解码速度或本机性能。
3. 只有供应商提供定义明确且范围匹配的生成耗时，才单独展示“服务端生成速率”。
4. 若保留客户端流式接收指标，必须标记其为接收侧指标；不能拿包含隐藏思考的总输出 token，直接除以短暂的可见文本接收窗口。
5. `reasoningTokens` 若为 `outputTokens` 的子集，不再次相加；缺少 token 计数或可信时长时显示“速率不可用”，不以字符数冒充供应商 token。

#### B. 修复样本配对与聚合

- 以 `sessionId + turn + step + attemptId + executionInstanceId` 作为测量归属；失败重试和成功请求分别保存。
- 每次请求保存单调时长、token 来源、模型、供应商、传输形式和测量质量。墙上时间仅用于日期展示，不用于跨电脑相减。
- 零时长、负时长、计时缺失、仅最终批量返回等不适合相应口径的样本，不进入该速率的分子和分母。
- 聚合计算采用合格样本的 `Σtokens / Σduration`，不平均各样本速率，不混合不同口径。费用统计保留所有实际 usage，不因速率样本被排除而丢失。
- 全程有效流式请求和极短请求分别进行测量质量判定；不能简单设定 9000 或某个速率上限，将异常值截断为“正常值”。

#### C. 执行来源与跨电脑隔离

- 标识请求实际执行后端与连接目标，区分当前浏览器所在电脑、执行后端和模型供应商。
- 后端实例、会话、请求尝试必须进入缓存键和聚合边界。相同轮次、步骤编号在另一台电脑上不能命中当前请求统计。
- 历史回放沿用持久化测量，不按回放或浏览器渲染速度重新计时。
- 速率详情显示供应商、模型、执行位置、统计口径和测量质量。缺少来源信息的旧记录显示来源未知，不推断归属。

#### D. 前后端及历史兼容

统一消息底部、会话统计、轨迹面板和后端投影的规则。新增测量结构和统计版本；旧日志缺少请求发送时间或执行来源时保留原记录，但不套用新公式伪造精确结果。升级投影缓存版本，防止旧异常聚合值继续被复用。

## 4. 验收矩阵

| 场景 | 预期结果 |
| --- | --- |
| 图片上传接口卡住或上传锁长期占用 | 阶段可见，在总预算内结束，保留准确原因 |
| 上传失败并满足内联回退条件 | 有回退事件，取消和权限错误不进入该分支 |
| 连接建立但服务不返回响应头 | 响应头期限生效，当前请求正确终止 |
| 非成功响应只返回部分正文后挂起 | 正文读取有界结束，不持续占用运行状态 |
| 持续 SSE 心跳而无有效输出 | 无有效进展期限生效，心跳不无限续期 |
| 正常文字、思考或工具参数持续输出 | 不误判为空闲，不重复执行工具 |
| 各阶段点击停止、随后重新发送 | 旧请求退出，新请求不受遗留锁或状态影响 |
| 已知 900 token、请求耗时 10 秒 | 请求平均输出速率为 90 tok/s；合成测试数据仅用于测试 |
| 单个零时长样本或与正常样本混合 | 零时长样本不抬高聚合速率，不影响费用统计 |
| 内容延迟后集中返回、隐藏思考占主要输出 | 不将短接收窗口作为全部输出的生成耗时 |
| 多次重试、模型切换 | token 与时间按尝试配对，终止状态与来源准确 |
| 两台电脑存在相同轮次和步骤编号 | 统计互不串用；同一会话跨设备查看读数一致 |
| 刷新、断线重连、快速回放历史 | 状态恢复准确，速率不因浏览器回放速度改变 |
| 缺少 usage、时长或来源的旧记录 | 明确缺失，不显示伪造的零值或精确速率 |

## 5. 实施与发布顺序

1. 在测试中建立上传卡住、响应头不返回、心跳空转、零时长聚合及跨实例隔离的可复现样本。
2. 优先修复附件准备与网络等待的期限和取消，并补充统一请求尝试及阶段测量。
3. 基于同一测量结构修复速率统计、前端展示与历史缓存兼容。
4. 执行相关传输、Agent 生命周期、统计投影及前端 DOM 测试；本机和另一台测试电脑使用相同构建验证。
5. 重新构建后端和 Web 产物，确认安装目录中实际运行程序的版本与构建修订；在正常维护窗口重启后验证当前页面。
6. 使用图片请求及纯文本请求复测，核对阶段日志、取消响应、速率分子分母、执行来源和刷新后结果；保留可回退的安装包。

完成标准：两个问题的故障场景均通过验证，运行中的安装版包含修复，正常模型输出不受影响，跨电脑统计归属可追溯。
