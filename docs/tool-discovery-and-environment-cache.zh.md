# 工具发现与环境能力缓存

Host 默认启用渐进式工具发现。核心文件、Shell、技能及发现入口直接可用；MCP 工具按需加载，超过 32 个可见工具时，非核心工具也进入检索目录。原始工具注册表、作用域过滤、审批和执行检查继续决定实际调用权限。

## 使用方式

寻找未知工具：

```json
{"query":"create github issue","limit":5}
```

调用 `tool_search` 后，匹配工具的完整参数返回，并在后续原生工具列表中保留。已知名称使用 `tool_describe`：

```json
{"names":["mcp__github__create_issue"]}
```

同一会话不需要每轮重新搜索。工具被卸载或作用域禁止后立即不可调用；定义变更后，需要重新加载。达到加载预算时，结果中的 `overBudget` 列出未加载工具，可以显式释放旧定义：

```json
{"release":["mcp__github__create_issue"],"names":["mcp__mail__search"]}
```

搜索采用名称加权 BM25、精确名称优先和子串匹配，支持中文双字词检索。无匹配时仍返回当前可见来源。搜索仅返回当前作用域允许的工具，不透露被禁止工具的名称。

代码模式继续使用 `run_code`，例如 `await tools.tool_search({query: "mail"})`。它保留现有完整工具绑定；原生模式的 schema 裁剪不强行改变代码模式执行约定。

## 环境诊断

`environment_probe` 查询固定能力目录：`python`、`node`、`git`、`rg`、`pwsh`、`ffmpeg`、`wps`。

```json
{"names":["python","wps"]}
```

结果包含实际路径、状态、版本、检查时间、缓存命中和首次探测耗时。Python 同时检查常见文档库能否被定位；检查使用隔离模式，不代表项目虚拟环境、用户 site-packages 或模块的原生依赖能成功导入。Node 复用 PTC 的权限模型、TypeScript 和 Worker 检查；PTC 不兼容不表示普通 JavaScript 完全不可用。WPS 只定位，不启动 Office。

有效结果会以简短环境上下文提供给后续任务。缓存失效或实际执行失败时可请求刷新：

```json
{"names":["python"],"refresh":true}
```

缓存规则：

| 项目 | 规则 |
| --- | --- |
| 成功或已定位 | 最长 24 小时 |
| 缺失、权限、超时及错误 | 最长 60 秒 |
| 并发 | 同项普通查询与同时开始的刷新合并探测 |
| 环境变化 | PATH、运行环境配置、用户/主机身份及 PATH 目录状态参与指纹 |
| 文件变化 | 程序大小或修改时间变化后失效 |
| Python 包变化 | 已记录的包目录状态变化后失效 |
| 取消 | 终止子进程，不保存取消为能力缺失 |
| 持久化 | 缓存目录中的 `environment-capabilities-v1.json`，上限 128 KiB |

诊断限定于 Host 执行环境，不证明沙箱或远程主机具有相同权限和依赖。实际文件操作、Office 自动化和项目命令仍经原有工具执行。缓存不扫描整块磁盘，也不存储密钥或完整环境变量。

## 配置

数据目录的 `tool-discovery.json` 在 Host 启动时读取；修改后重新启动 Host 生效。文件不存在时使用默认值。配置示例：

```json
{
  "enabled": true,
  "eagerLimit": 32,
  "listingChars": 4096,
  "maxLoaded": 96,
  "maxSchemaBytes": 131072,
  "deferredPrefixes": ["mcp__"]
}
```

`eagerTools` 可覆盖核心工具名称列表；通常保持缺省即可。`enabled: false` 恢复完整原生 schema 展示。字符和字节预算是确定性限制，不是精确 token 计费。

加载预算只覆盖延迟工具；核心工具和单个超过加载预算的定义保持直接可见，避免形成无法调用的工具。达到预算时不自动逐轮淘汰工具，以减少反复加载和缓存抖动。

## 状态恢复与限制

加载状态保存在版本化的 `tools/discovery` 可忽略事件中，包含名称和声明摘要，不依赖聊天内容或压缩摘要。恢复时重新核对当前定义、预算和权限，分叉使用分叉边界内的状态。旧版读取器可以跳过这些事件。

内存最多缓存 64 个会话的发现状态；冷恢复最多检查最近 8192 个事件。超出恢复窗口且未找到快照时，目录会提示重新按名称加载，不会猜测历史状态。

通用提供方使用普通 function schema。首次加载或显式释放会改变工具集，可能使提供方的提示前缀缓存失效；稳定后不重复改写。该实现不依赖 OpenAI 专属的 `tool_search_output` 协议，因此不能假定所有模型都获得追加式工具加载的缓存收益。

效果评估应同时记录模型实际输入/缓存用量、发现调用次数、任务耗时和成功率。工具返回的 `catalogCount`、`loadedCount`、`loadedSchemaBytes` 及环境结果的 `cacheHit` 用于诊断，不代替提供方账单。
