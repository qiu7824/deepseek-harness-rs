# 0.1.3-alpha.38

## 桌面体验与模型选择

- Flutter 统一字体、控件尺寸、语义图标、状态色和中文提示；设置导航按功能分组，提供命令搜索、独立统计浮层及工作台起始页。
- 型号与思考等级合为输入框内的紧凑入口，菜单分层选择并支持逐级返回；模型目录缓存即时展示，连续切换保留最后一次选择意图，新会话默认值有序后台保存。上下文和压缩设置使用独立入口。
- 账号面板列出已连接或需要重新登录的服务，可直接重新登录或进入对应设置；账号设置区分已连接和可用服务。插件按模块名称打开，独立主页面与设置共用列表。
- 会话与工作区行在悬停或聚焦时显示操作菜单，与右键菜单一致；工作区展开与新会话目标选择分开处理。
- 未发送草稿按 Host 和工作区保存，关闭窗口前完成偏好写入；保存失败时保留窗口及内容。切换工具标签保留阅读位置和草稿，隐藏预览按时间或资源预算释放后可恢复位置。
- 修复 Windows 关闭窗口时的崩溃和退出延迟；窗口在消息循环内销毁，原生窗口释放先于 COM 清理，并按显示器可用区域定位。
- 连接到旧 Host 时，缺失接口的 HTTP 404/405 显示具体功能不受支持及更新提示。指定偏好文件加载的设置写回原文件，测试不再写入真实桌面偏好。
- 回合结束后在回复下方显示紧凑产物卡，提供文件预览、操作和完整产物列表入口。

## Claude 与 Devin 兼容

- 修复 Claude 直接调用或经 Devin 转发时拒绝部分工具定义的问题，文件整理和临时资源工具可使用兼容的对象参数结构；实际执行仍按原始工具规则校验参数。
- Devin 流式错误保留协议错误码，参数拒绝不再误报为模型不可用。

## 文件访问与附件

- 宿主文件工具按会话身份隔离应用私有目录和受管临时资源；凭据提供者的实际文件路径独立保护，支持自定义配置目录和数据目录。
- `read`、`read_image`、`glob`、`grep`、编辑器查看、代码索引、Office 渲染和产物提交共用读取边界。路径解析与实际读取均核对规范路径；递归搜索在启动前检查受保护子目录。
- 当前会话正式接收的附件按精确文件授予读取权限；工具参数和元数据中的附件标识不能获得其他会话的附件访问权。
- 原生执行支持精确文件读取根。附件读取根有数量和长度预算：用户上传的内容优先，其次是最新的工具图片，已清理的附件不再下发，长会话的截图和视频帧不会撑爆命令行；未下发的图片可通过 `read_image` 取得会话内副本。无效根的诊断包含具体路径。
- 按附件 ID 读取图片时提供当前会话独立的临时副本路径，供脚本使用；共享附件对象保持不可变。
- 原生执行的受管临时目录授权限定到当前会话资源，避免授权整个共享临时资源目录。
- 旧权限按沙箱账户完成首次迁移；后续核对目录身份和授权子树，新增文件继承隔离规则。
- 原生 ACL 操作使用支持长路径的 Win32 文件名，长会话目录可正常迁移、精确授权及撤权；失败诊断优先保留系统错误号。
- 代码执行在沙箱启动确认后开始计算程序预算；首次权限迁移有独立启动上限，取消可中断启动或执行。
- Git 执行副本直接复制当前工作区内容，不运行仓库定义的检出转换或文件系统监控程序。

## 执行流程

- 移除任务契约、任务验收工具与接口、完成门禁、自动验收续接、验收状态卡和契约状态上下文。普通工具执行、目标、计划、后台作业及定时任务保持独立运行。
- 技能版本由用户手动创建、启用、撤回和恢复，不依赖任务样本或验收数据库，也不显示自动验证结论。
- Office 输入的 ZIP/XML 结构与活动内容检查由独立模块执行。
- 自动发现的 PowerShell、Node 和 Python 排除其他产品的私有缓存运行时，首次选定的路径持久保存；缺失时报告失效，不静默切换程序。
- 文件与 Office 工具不依赖 Shell 环境指纹；执行类工具继续校验实际运行环境与权限。
- 人工审批等待不消耗工具或 Node 程序的执行预算；审批自身超时、停止和纯计算上限继续生效。同一轮同类审批超时后不重复等待。
- 相同执行环境下反复出现启动失败时停止重试；更换命令、工作目录或工具别名不能清除失败记录。
- 文档工作区不注入 Host 源码、Web 热更新或前端开发命令；默认工具列表精简，扩展工具按需发现。远端终端明确限定为远端操作。

## Office 数据与文件整理

- `office_read` 直接读取 DOCX 段落、表格和 XLSX 单元格；返回位置、原始值、单元格类型、数字格式及公式缓存标识，不执行公式或外部链接。
- `office_write` 直接生成真实 DOCX/XLSX，无需 Shell、Python 或沙箱进程。字符串按文本保存，保留电话号码、前导零和等号开头的字面值。
- 覆盖 Office 文件须经明确人工批准，并核对批准前的文件版本；取消、目标变化或发布失败不会删除原文件。结构检查不等同于内容对照或视觉检查。
- `file_manage` 支持经人工批准后重命名单个文件或移入可恢复回收区；拒绝目录递归、链接、覆盖已有目标及工作区外文件。
- 普通文本写入、临时区写入、候选产物交付和文件重命名都核对二进制扩展名与实际内容，避免将 HTML 改名为无法打开的文档。

## 会话恢复与界面

- Windows 程序、托盘、安装器和浏览器标签图标统一采用白色圆角底框与黑色鲸鱼标识。
- 崩溃后的会话修复先关闭未完成压缩，再结束对应步骤和回合；手动压缩保留命令身份，重复恢复不重复补写结束事件。
- 继承历史边界终止上级会话遗留的压缩状态，避免新会话持续误报压缩正在进行。
- Web 与 Flutter 将自动状态同步显示为“运行信息更新”，重复调用检测显示为“重复调用提醒”；内容默认折叠，可展开核对原始信息。
- 运行上下文仅注入变化的命名分节；冷恢复重放增量链，压缩移除依赖或导入缺失链时重新建立完整基线。
- Flutter 的新会话使用侧栏当前选择的工作区，已有会话继续显示自身工作区。
- Flutter 增加 Computer Use 面板，可查看并加入模型的桌面操作会话。
- 长流式答复采用有界分段合并，并在完整消息替代已覆盖片段后释放缓存，保留首个片段时间及冷恢复边界。
- 旧安装位置的沙箱辅助程序缺失时，重新绑定当前发行包中的已验证程序，并保留选定的实现、网络策略及状态目录。

## 升级与发行包

升级前等待当前任务结束，保存草稿并关闭客户端及待替换的 Host。安装版沿用原安装目录；便携版解压到新目录后继续使用原数据根。保留原有会话、附件、凭据、设置和桌面偏好，替换应用文件时不要删除用户数据目录。Flutter 桌面版和 Web 核心版分别选用对应产品、平台及架构的包。

完整发行包含 13 个应用包，以及合并校验文件 `SHA256SUMS.txt`：

| 平台 | Web 核心版 | Flutter 桌面版 | 包数 |
| --- | --- | --- | --- |
| Windows x86_64 | ZIP 便携包、EXE 安装包 | ZIP 便携包、EXE 安装包 | 4 |
| Linux x86_64 | TAR.GZ 便携包、DEB 安装包 | TAR.GZ 便携包 | 3 |
| macOS x86_64 | TAR.GZ 便携包、PKG 安装包 | TAR.GZ 便携包 | 3 |
| macOS aarch64 | TAR.GZ 便携包、PKG 安装包 | TAR.GZ 便携包 | 3 |

Web 核心包的 `PACKAGE.json` 标明版本、平台、架构和启动入口；Flutter 完整包的 `DESKTOP.json` 记录客户端及所带 Host 的构建身份和文件摘要。Host 的 `--build-info` 提供版本、源码提交和构建时修改状态；下载文件通过 `SHA256SUMS.txt` 核对 SHA-256。完整包随附 Web 资源、插件、预设、Node、ripgrep 和许可证。Linux 受限执行仍需系统 `bubblewrap`。

## 当前限制与验证范围

## English

### Desktop experience and model selection

- Unify Flutter typography, control sizes, semantic icons, status colors and Chinese tooltips. Group Settings by function and add command search, separate statistics popovers and a workbench start view.
- Combine model and reasoning selection into one compact composer control, with nested menus and step-by-step navigation. Show cached catalogs immediately, retain the latest selection during rapid changes, and save new-conversation defaults in order in the background. Context and compaction settings have a separate entry.
- List connected providers and providers requiring re-login in the account panel, with direct re-login and Settings links. Group connected and available providers in account settings. Resolve plugin pages by module name and share the list between the main plugin page and Settings.
- Expose conversation and workspace row menus on hover or focus, matching the context menu. Keep workspace expansion separate from selecting the target for a new conversation.
- Preserve unsent drafts per Host and workspace, and save preferences before closing. Keep the window and content available if saving fails. Preserve reading positions and drafts across workbench tabs; reclaim hidden previews within time or resource budgets and restore their positions when reopened.
- Fix Windows crashes and delayed shutdown when closing the window. Destroy the window within the message loop, release native windows before COM cleanup, and position the window inside the monitor work area.
- Report unsupported features and an update hint when an older Host returns HTTP 404/405 for a missing route. Preferences loaded from a specified file save back to that file, and tests no longer write real desktop preferences.
- Show a compact artifact card below the completed reply, with previews, file actions and access to the full artifact list.

### Claude and Devin compatibility

- Make tool definitions compatible with Claude directly and through Devin, including file management and temporary-resource tools. Requests use a compatible object parameter structure; execution still validates arguments against the original tool rules.
- Preserve Devin streaming protocol error codes so rejected arguments are not reported as an unavailable model.

### File access and attachments

- Isolate Host private directories and managed temporary resources by session identity. Protect credential providers' actual file paths, including custom configuration and data directories.
- Apply the same read boundary to `read`, `read_image`, `glob`, `grep`, editor views, code indexing, Office rendering and artifact submission. Check canonical paths during resolution and actual reads, and check protected descendants before recursive search starts.
- Grant access to the exact attachment files accepted by the current session. Attachment identifiers in tool arguments or metadata do not grant access to other sessions' attachments.
- Support exact-file read roots for native execution. Bound root count and length, prioritize user uploads and recent tool images, and omit cleaned attachments. Long screenshot or video histories cannot exhaust command-line space; `read_image` can provide a session copy of an omitted image. Invalid-root diagnostics identify the path.
- Provide a session-owned temporary image copy when reading by attachment ID, while keeping shared attachment objects immutable. Limit temporary-resource permissions to the current session's resources.
- Migrate existing permissions once per sandbox account, then verify directory identity and authorized subtrees. New files inherit the isolation rules. Native ACL operations support long Windows paths for migration, exact grants and revocation, with system error codes retained in diagnostics.
- Start the program budget after sandbox startup is confirmed. Initial permission migration has a separate startup limit; cancellation can interrupt startup or execution.
- Copy Git execution workspaces directly from current files without running repository checkout filters or filesystem-monitor programs.

### Execution flow

- Retire task contracts, task-acceptance tools and APIs, completion gates, automatic acceptance continuations, acceptance cards and contract context. Ordinary tools, goals, plans, background jobs and schedules continue independently.
- Let users manually create, enable, withdraw and restore skill versions, without task samples, an acceptance database or automatic validation claims.
- Check Office ZIP/XML structure and active content through a dedicated module.
- Exclude other products' private cached runtimes when discovering PowerShell, Node and Python. Persist the selected executable path and report a missing runtime rather than silently switching programs.
- File and Office tools do not depend on a Shell environment fingerprint. Execution tools still verify their actual environment and permissions.
- Human approval waits do not consume tool or Node program execution budgets. Approval timeouts, cancellation and computation limits remain effective; repeated approval timeouts of the same kind do not start another wait in the same turn.
- Stop retrying repeated startup failures in the same execution environment. Changing the command, working directory or tool alias does not clear the failure record.
- Keep Host source, Web hot-reload instructions and frontend development commands out of document workspaces. Keep the default tool list compact, discover extensions as needed, and scope remote terminals to remote operations.

### Office data and file management

- `office_read` reads DOCX paragraphs and tables and XLSX cells directly, including positions, raw values, cell types, number formats and formula-cache markers. It does not execute formulas or external links.
- `office_write` creates real DOCX/XLSX files without Shell, Python or a sandbox process. Store strings as text, preserving phone numbers, leading zeroes and literal values beginning with an equals sign.
- Require explicit human approval and a file-version check before overwriting Office files. Cancellation, target changes or publication failures preserve the original file. Structural checks do not replace content or visual review.
- `file_manage` renames one file or moves it to a recoverable recycle area after human approval. Reject recursive directory operations, links, overwrites and files outside the workspace.
- Check binary extensions against actual content on text writes, temporary writes, artifact publication and renames, preventing HTML from being presented as an unreadable Office document.

### Session recovery and interface

- Use a white rounded frame and black whale consistently for Windows application, tray, installer and browser icons.
- Close interrupted compaction before ending its steps and turn during crash repair. Preserve manual-compaction command identity and avoid duplicate end events on repeated recovery. Inherited history boundaries terminate unfinished parent compaction state.
- Show automatic status updates and repeated-call reminders as collapsed entries that can be expanded to inspect the original information.
- Inject only changed named runtime-context sections. Replay the incremental chain on cold recovery and establish a new full baseline when compaction or import removes a dependency.
- Use the sidebar's selected workspace for new Flutter conversations while keeping existing conversations in their own workspace. Add a Computer Use panel for viewing and joining the model's desktop session.
- Merge long streamed replies in bounded segments, releasing covered fragments when a full message replaces them while retaining first-fragment timing and recovery boundaries.
- Rebind missing sandbox helpers from an older installation to the verified helpers in the current package, preserving the selected implementation, network policy and state directory.

### Upgrading and packages

Wait for active tasks to finish, save drafts, and close the client and the Host being replaced before upgrading. Installer upgrades retain the installation directory; portable upgrades can be extracted to a new directory while retaining the existing data root. Preserve sessions, attachments, credentials, settings and desktop preferences, and keep user data directories when replacing application files. Select the matching product, platform and architecture for Flutter desktop or Web core.

The complete release consists of 13 application packages and the combined `SHA256SUMS.txt` file:

| Platform | Web core | Flutter desktop | Packages |
| --- | --- | --- | --- |
| Windows x86_64 | Portable ZIP, EXE installer | Portable ZIP, EXE installer | 4 |
| Linux x86_64 | Portable TAR.GZ, DEB installer | Portable TAR.GZ | 3 |
| macOS x86_64 | Portable TAR.GZ, PKG installer | Portable TAR.GZ | 3 |
| macOS aarch64 | Portable TAR.GZ, PKG installer | Portable TAR.GZ | 3 |

Web core's `PACKAGE.json` identifies its version, platform, architecture and launcher. Flutter's `DESKTOP.json` records client and bundled Host identities and file hashes. Host `--build-info` reports the version, source commit and build-time modification state; verify downloaded files against `SHA256SUMS.txt`. Complete packages include Web assets, plugins, presets, Node, ripgrep and licenses. Confined execution on Linux still requires the system `bubblewrap` package.

### Limits and verification scope

- These notes describe the current implementation. Historical candidate tests and installations do not establish the verification status of this release's artifacts. See the [desktop platform record](../../docs/desktop-platforms.zh.md) for platform-specific build, installation and native testing scope.
- Native windows, clipboard, shortcuts and installation upgrades on macOS/Linux still require testing on those platforms. Component tests do not replace real Chinese IME, screen-reader or operating-system display-scaling checks.
- Flutter one-click updates, complete onboarding and the full upstream Web 0.2.0 replacement remain follow-up work. The upstream build chain and Remote contract inventory are prepared; the new Web client is not yet integrated with the current Host.
- Verify real provider accounts, remote devices, voice services, Office content and visual layout separately. Readable Office structure does not establish correct content or layout. Fixed resource-test scenarios do not establish long-running mixed-load performance for the real Host and Computer Use.
