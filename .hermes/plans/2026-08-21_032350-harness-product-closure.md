# DeepSeek Harness 产品封板实施计划

> **执行约束：** 按10个宏阶段推进；每阶段集中完成约10%的可记账产品能力，再统一编译、专项测试、真实Host测试、真实浏览器修复和实装。不得用页面数量、代码量或单元测试数量代替生产可用性。

**目标：** 将rc.8现有底层能力贯通为稳定、可配置、可审计、支持多模型并行与长上下文工作的正式Web产品，并补齐语音、技能、桌面控制、记忆等缺失能力。

**架构原则：** 优先接通已有crate和正式服务，不重复实现默认模型、会话标题、compaction、token meter、审批、permission presets和skill。新增能力保持插件化或服务化，避免扩大核心模型工具面；配置与凭据分离，所有会话和数据根必须显式、持久并支持重启恢复。

**技术栈：** Rust 1.97.1、Cordis服务组合、JSONL/Zstd会话持久化、SQLite/Storage Domain、Web RPC/SSE、现有DeepSeek Harness Web bundle、Windows真实Chrome。

## 一、需求分维与完成定义

| 产品维度 | 用户要求 | 当前判断 | 最终完成证据 |
|---|---|---|---|
| 模型入口 | 默认模型可读；未选模型的对话也要显示模型 | `agent-default-model` crate已存在，正式Host/模型选择UI未完整贯通 | 新会话首屏显示默认模型；未显式选择时请求和页面一致；重启保持 |
| DeepSeek首轮 | 不应必须先说“你好”才能得到不同/正常思考 | 待做请求级差异复现 | 同一新会话分别直接任务/先问候再任务，比较system、header、provider、缓存与事件，行为一致且无隐式初始化缺口 |
| 工作区 | 首屏先列所有盘符，再逐级进入目录 | 后端当前目录首屏语义错误 | Windows真实浏览器首屏只显示可访问盘符/网络根；点击D盘后再列目录；刷新和选择正确 |
| 会话命名 | 新建对话按正式规则自动命名 | `session-title*` crate已存在，正式组合未接通 | 首条有效用户消息触发标题；失败有确定性回退；手工重命名优先；重启保持 |
| 长上下文UI | 类似Markdown章节跳转/阅读进度 | token meter/compaction已有，缺UI导航 | 超长会话显示滚动进度、章节锚点、跳转和当前位置；分页加载后索引正确 |

| 数据目录 | 不使用Temp；设置工作/缓存/环境/测试目录 | 正式根目前使用Temp实测，缺目录配置域 | 配置保存在稳定用户目录；四类目录可配置、验证、迁移/拒绝、重启恢复 |
| 安全盾 | 审计、目录读写范围、删除确认、审批模式/超时 | approval/permission presets已有，缺统一策略与UI | 所有高风险操作统一策略决策、明确审批、超时、审计记录和重启策略 |
| Skill/CUA | 参考Hermes | skill已有，Computer Use缺正式边界 | Skill目录/启停/刷新可管理；Computer Use独立插件/服务，能力授权明确 |
| 语音 | 参考Hermes STT/TTS | 当前正式链缺失 | 可配置STT/TTS provider；录音→转写→发送；回复→播放；无凭据时明确降级 |
| 记忆/压缩 | 参考Codex；已有则不新增 | compaction已有，长期记忆缺失 | 先接通原生compaction；长期记忆独立、可审计、可关闭、跨会话生效 |

## 二、宏阶段路线（每阶段约10%）

### 阶段1（0%→10%）：基础入口纠偏——默认模型、盘符根、稳定数据根

**目标：** 先修复用户每天必经的三个入口，建立后续功能的稳定基础。

**主要工作：**

1. 将`dsh-agent-default-model`接入正式Host和设置域。
2. 新会话创建前读取默认模型；模型按钮始终显示解析后的provider/model/effort，不再显示空“选择模型”。
3. 区分“会话显式模型”和“默认模型继承”，页面明确标注继承状态。
4. 重构Windows Browse首屏：新增虚拟“此电脑”根，仅返回所有可访问盘符/可访问UNC入口；不得自动展开C盘。
5. 点击盘符后才调用真实目录枚举；断连映射盘设置短超时并标记不可用。
6. 定义稳定产品根，默认位于用户本地应用数据目录，不再把Temp当正式配置根。
7. 提供旧Temp根的只读检测和显式迁移提示；不自动覆盖、不读取凭据明文。

**预计修改：**

- `crates/host/dsh-host/src/lib.rs`
- `crates/core/agent-default-model/src/index.rs`
- `crates/host/apiproxy/src/proxy.rs`
- `crates/host/directory-picker-browse/src/index.rs`
- `crates/host/directory-picker-browse/tests/service.rs`
- `crates/host/dsh-cli/src/run_profile.rs`
- `web/dist/plugins/ui-conversation.js`
- 设置相关正式bundle

**阶段验收：**

- 新会话未手选模型也显示并使用默认模型。
- 两个已有会话仍显示各自持久模型。
- 工作区选择首屏显示所有可访问盘符，不列C盘文件。
- 默认正式配置根不含`Temp`。
- 同根重启后默认模型、工作区和会话状态一致。

### 阶段2（10%→20%）：DeepSeek首轮一致性与会话命名

**目标：** 解决“先说你好再工作思维链不同”和新会话无正式标题。

**主要工作：**

1. 建立两条完全相同配置的E2E：直接任务；先“你好”再同任务。
2. 对比system prompt字节、request/header、工具schema、reasoning effort、provider/model、上下文装配、缓存边界和SSE首块。
3. 修复首轮初始化缺口，不通过自动插入“你好”或隐藏消息解决。
4. 接通`session-title`与合适的`session-title-*-llm` provider。
5. 标题触发规则：第一条非空、非命令、非纯附件用户请求；限制长度、清理换行；失败使用确定性中文摘要。
6. 手工重命名具有最高优先级，自动标题不得覆盖。

**阶段验收：**

- 两条DeepSeek路径的核心请求配置一致，仅历史消息差异可解释。
- 首轮实时Think和直接任务均正常。
- 新会话在首条请求后自动得到正式标题，刷新/重启后保持。

### 阶段3（20%→30%）：多模型并行与会话级调度

**目标：** 证明并修复多个模型、多个会话同时运行的产品链。

**主要工作：**

1. 明确并发模型：每会话单活动turn；多会话可并行；同会话消息走queue/steer。
2. 为全局状态增加`runningBySession`/provider/model可观测映射。
3. 消除全局单例取消、进度、模型选择和附件解析的串扰。
4. 并发执行DeepSeek与gpt图片/文本请求；分别取消其中一个，另一个继续。
5. 增加全局并发上限和每provider上限设置，不静默串行化。
6. 页面显示每个会话的模型、运行状态、等待时长和错误。

**阶段验收：**

- 至少两个不同模型会话真实并行。
- 独立取消、超时、SSE结束、持久事件和恢复无串扰。

### 阶段4（30%→40%）：长上下文导航、Token进度与Compaction接通

**目标：** 把已有token meter和compaction变成长会话可用产品能力。

**主要工作：**

1. 接通`dsh-token-meter`、`session-checkpoint-policy`和`dsh-compaction`正式组合。
2. 页面增加上下文用量条：已用/上限/压缩阈值/剩余。
3. 从用户消息、助手标题、Markdown H1–H3、工具阶段生成会话章节索引。
4. 增加右侧或滚动条内嵌进度轨道、当前位置、点击跳转。
5. 分页加载历史后增量合并索引，不读取全日志阻塞首屏。
6. 压缩事件作为明确节点显示，可展开查看保留范围和摘要。

**阶段验收：**

- 大型会话滚动、跳转、分页、压缩后锚点正确。
- 压缩前后工具配对、角色交替和缓存边界不破坏。

### 阶段5（40%→50%）：稳定目录体系与设置中心

**目标：** 建立正式、可迁移、可审计的数据目录模型。

**目录维度：**

- 配置根：settings、非秘密配置、插件启停。
- 工作目录：用户项目默认根/最近工作区。
- 缓存目录：可再生成内容、模型/图片临时转换、索引缓存。
- 环境目录：运行环境、工具链、隔离环境引用；不得存明文凭据。
- 测试目录：临时测试根，正式Host默认不使用。
- 会话/数据目录：JSONL、SQLite、附件、domain storage。

**主要工作：**

1. 新增统一`PathLayout`服务和settings schema。
2. 路径必须绝对、可创建、权限可验证、不得互相危险嵌套。
3. 设置页可选择和验证各目录，显示占用与状态。
4. 修改后区分热生效/重启生效；需要迁移时给出预览和确认。
5. 测试Host继续强制隔离临时根，正式Host禁止意外读取测试目录。

**阶段验收：**

- 四类用户要求目录均可设置并重启恢复。
- 配置文件与凭据引用不再落Temp。
- 路径迁移失败可回滚，不产生双根分裂。

### 阶段6（50%→60%）：安全盾——策略、审批、审计和超时

**目标：** 在现有sandbox、permission presets和approval上建立统一安全产品层。

**主要工作：**

1. 定义安全模式：智能、手动、关闭；默认智能。
2. 文件能力分级：只读目录、可写目录、禁止目录、删除需确认目录。
3. 删除文件/目录、覆盖、跨工作区写、执行高风险命令均进入统一审批。
4. 审批请求携带工具、目标、规范化路径、风险、原因、预期影响。
5. 审批超时可配置；超时默认拒绝，不转为允许。
6. “本次允许/始终允许/拒绝”状态持久化并可重置。
7. 安全审计页按会话、工具、路径、决策、耗时筛选；不记录密钥和文件正文。
8. 路径检查使用canonical identity并防符号链接/重解析点逃逸。

**阶段验收：**

- 允许读取目录正常；越界读取拒绝。
- 删除目录必需明确确认；超时拒绝。
- 审计记录与实际工具结果一致，重启后可查询。

### 阶段7（60%→70%）：Skill与Computer Use产品化

**目标：** 参考Hermes的边缘扩展原则，将Skill和Computer Use接成可管理能力。

**Skill：**

1. 接通现有`dsh-skill`、`skill-filesystem`、`tool-skill`到正式Host。
2. 设置页显示来源、状态、触发说明、依赖与错误。
3. 支持用户目录、项目目录与内置Skill优先级，防路径逃逸。
4. 变更热刷新，运行中的会话保持稳定缓存边界，新会话生效。

**Computer Use：**

1. 作为独立可禁用插件/服务，不塞入核心工具。
2. 采用截图→元素身份→后台动作→验证→受控升级流程。
3. 现有浏览器页面优先使用可信页面协议；原生UI使用后台驱动。
4. 权限、前台升级、文件上传、系统对话框纳入安全盾。
5. 无驱动/权限不足时提供doctor诊断，不静默失败。

**阶段验收：**

- Skill启停、加载、刷新、会话生效边界明确。
- Computer Use后台点击/输入/验证可用；前台升级需审批并有审计。

### 阶段8（70%→80%）：语音输入与语音回复

**目标：** 参考Hermes配置模型接入STT/TTS，不绑定单一商业服务。

**主要工作：**

1. STT接口：local faster-whisper、OpenAI兼容、可扩展provider。
2. TTS接口：Edge免费默认、OpenAI兼容、可扩展provider。
3. 设置项仅保存provider和非秘密参数，密钥只走Credentials引用。
4. Web录音按钮、权限状态、录音时长、上传/转写进度、取消。
5. 转写文本进入编辑框，用户确认后发送；默认不自动发送。
6. 回复语音支持单次播放、自动播放开关、速度/音色、停止。
7. 音频缓存进入缓存目录并有大小/保留策略。

**阶段验收：**

- 无凭据Edge TTS可播放；本地/测试STT可转写。
- 麦克风拒绝、上传失败、转写超时均明确可恢复。

### 阶段9（80%→90%）：长期记忆与上下文治理

**目标：** 保留Harness已有compaction，新增独立且可审计的跨会话记忆，不混入历史消息。

**主要工作：**

1. 复核`dsh-compaction`覆盖面，补正式Host接线，不另造压缩器。
2. 参考Codex/Hermes：压缩只替换允许的旧上下文窗口，保持系统前缀和工具配对。
3. 新增Memory服务：用户偏好、项目事实、环境事实分域；任务进度不作为长期记忆。
4. 写入策略：默认需用户批准或明确自动策略；显示来源会话和时间。
5. 注入采用稳定、限额、可追踪的context block，不中途改写系统提示词。
6. 设置页支持查看、编辑、删除、关闭、导出。
7. 与session reference、checkpoint、token meter联合测试。

**阶段验收：**

- 长会话触发压缩后继续工作，角色/工具/缓存正确。
- 跨会话记忆可命中、可追溯、可删除；关闭后不注入。

### 阶段10（90%→100%）：总封板、迁移、文档与生产验收

**目标：** 将前九阶段合并为单一正式产物并完成全链路验收。

**主要工作：**

1. 原配置根只读检测与显式迁移；凭据引用不泄漏。
2. 所有设置的默认值、验证、错误、重启恢复检查。
3. 两模型并行、图片、语音、审批、Skill、Computer Use、长上下文、记忆组合场景。
4. 正式Chrome逐项点击，检查Network、Console、WebSocket、持久化和Host重启。
5. 运行fmt、diff、目标Strict Clippy、相关crate、生产Web E2E、完整workspace。
6. 最新代码后独立只读P0/P1复核。
7. 停止所有临时服务，清理隔离浏览器/脚本/测试目录，只保留正式服务和规范内日志。

**最终完成标准：**

- 11项要求均具有真实生产入口证据。
- 不依赖Temp配置根。
- 不修改用户provider、密钥、账号或默认模型值；只实现配置能力。
- 单一正式Host和正式Web产物，无额外固定端口。
- 未完成/外部阻断明确列出，不以测试数量夸大完成度。

## 三、测试节奏

每个宏阶段严格采用同一节奏：

1. 阶段开始：写本阶段垂直RED，确认失败点是业务断言。
2. 集中实现：完成该阶段约10%的全部跨层工作，中途只运行最快的编译/单测反馈，不做全workspace。
3. 集中测试：格式→专项单测→领域测试→正式Host E2E→真实Chrome。
4. 集中修复：只修本阶段和新回归，重新执行阶段门禁。
5. 实装：停止旧`dsh.exe`→重建→用稳定配置根启动动态端口→真实页面验收。
6. 记账：只有真实入口和重启恢复通过的内容计入该10%。

## 四、关键风险与处理

- **工作树高度脏：** 不重置、不覆盖无关改动；阶段patch按文件/功能小块提交前验证。
- **现有bundle为构建产物：** 每阶段先定位对应源包；若当前仓库仅交付dist，则保留可复现的bundle更新流程，避免手改不可追溯。
- **模型思维链差异：** 只修请求和生命周期不一致；不伪造、不自动插入问候、不强迫模型泄露隐藏推理。
- **目录迁移：** 默认只检测和预览；显式确认后执行原子迁移，失败回滚。
- **安全功能：** 审批和审计不能只在UI实现，必须在Host工具执行边界强制。
- **语音/Computer Use外部依赖：** 功能在依赖缺失时可诊断、可禁用；不把外部登录状态算作代码完成。
- **长期记忆：** 与会话历史、compaction、Skill分开存储，避免提示缓存和隐私边界混乱。
